# 중첩 클래스

---

## 📄 본문
### 중첩클래스
![[../attachments/screenshots/중첩클래스.png]]

중첩은 어떤 다른것이 내부에 위치하거나 포함되는 구조적 관계입니다.
내부는 나의 내부에 있는 나를 구성하는 요소입니다.

중첩 클래스에는 총 4가지가 있으며, 크게 2가지로 분류한다.
- 정적 중첩 클래스
- 내부 클래스
	- 내부 클래스
	- 지역 클래스
	- 익명 클래스
```java
class Outer {
	...
 	//정적 중첩 클래스
 	static class StaticNested {
 		...
 	}
    
 	//내부 클래스
 	class Inner {
 		...
 	}
}
---
class Outer {
	
    public void process() {
 		//지역 변수
 		int lcoalVar = 0;
 
 		//지역 클래스
 		class Local {...}
 
 		Local local = new Local();
 	}
}
```

#### point
중첩 클래스의 선언 위치
- 정적 중첩 클래스 -> 정적 변수와 같은 위치
- 내부 클래스 -> 인스턴스 변수와 같은 위치
- 지역 클래스 -> 지역 변수와 같은 위치

##### 중첩 클래스를 사용하는 이유
바깥 클래스의 private 필드에 접근 할 수 있다. 그만큼 긴밀하게 연관되기 때문에 캡슐화를 높일 때 사용한다.
또한, 논리적인 그룹화를 시킬 수 있다.
특정 클래스가 특정 클래스 내에서만 사용된다면 해당 클래스에 포함하는것이 더 그룹화가 되기 때문에 다른 곳에서 사용될 필요가 없는 중첩 클래스가 외부에 노출 되지 않는다는 장점이 있다.



### 정적 중첩 클래스
정적 중첩 클래스 앞에는 static이 붙으며, 바깥 클래스의 인스턴스에 소속되지 않아 바깥 클래스의 인스턴스 맴버 변수에 접근 할 수 없다. 즉, 바깥이 private인 경우에도 접근 할 수 없는 것이다.
서로 다른 클래스를 중첩한것 이기 때문에 서로 아무런 관계가 ㅇ벗다.

#### point
바깥 클래스의 인스턴스 맴버에는 접근할 수 없다.
바깥 클래스의 클래스 맴버에는 접근 할 수 있다. (private도 가능하다.)
```java
public class NestedOuter {

    private static int outClassValue = 3;
    private int outInstanceValue = 2;

    static class Nested {
        private int nestedInstanceValue = 1;

        public void print() {
            // 자신의 멤버에 접근
            System.out.println(nestedInstanceValue);

            // 바깥 클래스의 인스턴스 멤버에는 접근할 수 없다.
            //System.out.println(outInstanceValue);

            // 바깥 클래스의 클래스 멤버에는 접근할 수 있다. private도 접근 가능
            System.out.println(outClassValue);
        }
    }
}
```

### 내부 클래스
static 없이 내부 클래스를 만든다.
바깥 클래스의 객체에 필드에 접근 할 수 있다.
내부 클래스는 바깥 클래스의 인스턴스 참조를 가지게 된다.
바깥 클래스의 객체가 생성되야 내부 클래스의 객체를 생성할 수 있다.

#### point
바깥 클래스의 인스턴스 맴버에 접근 가능
바깥 클래스의 클래스 맴버에 접근 가능
```java
public class InnerOuter {

    private static int outClassValue = 3;
    private int outInstanceValue = 2;

    class Inner {
        private int innerInstanceValue = 1;

        public void print() {
            // 자기 자신에 접근
            System.out.println(innerInstanceValue);

            // 외부 클래스의 인스턴스 멤버에 접근 가능, private 접근 가능
            System.out.println(outInstanceValue);

            // 외부 클래스의 클래스 멤버에 접근 가능, private 접근 가능
            System.out.println(outClassValue);
        }
    }
}
```

### 지역 클래스
지역 클래스는 지역 변수와 같이 코드 블럭 안에서 정의된다.
지역 변수와 지역 클래스의 객체는 다른 생명 주기를 가진다.
지역 클래스 객체도 객체이기 때문에 GC 전까지 생존한다.
따라서, 지역 클래스는 객체를 생성할 때 필요한 지역 변수를 먼저 캡처하여 객체에 보관한다.
지역 클래스의 객체를 통해 지역 변수에 접근하면, 객체에 있는 캡처한 캡처 변수에 접근 시킨다.
그만큼 중간에 값이 변하면 안된다. final 키워드를 통해 불변성을 보장해야되는 문법을 가지고 있다.

### 익명 클래스
익명 클래스는 지역 클래스의 특별한 종류 중 하나이다.
익명 클래스는 지역 클래스이지만, 클래스의 이름이 없다는 특징을 가지고 있다.
```java
//익명 클래스 - 지역 클래스의 선언과 생성을 한번에 
Printer printer = new Printer(){ 
//body
}
```

클래스의 본문을 정의하면서 동시에 생성한다.
익명 클래스는 부모 클래스를 상속 받거나, 인터페이스를 구현해야한다.
그렇기 때문에 익명 클래스를 사용할 때는 상위 클래스나 인터페이스가 필요하다.

#### point
익명 클래스는 말 그대로 이름이 없기 때문에 생성자를 가질 수 없다. (기본 생성자만 존재)
익명 클래스를 사용하면 클래스를 별도로 정의하지 않고도 인터페이스나 추상 클래스를 즉석에서 구현 할 수 있어 코드가 간결해진다.

##### 익명 클래스 vs 람다 표현식
익명 클래스는 일반적인 클래스 처럼 다양한 인터페이스와 클래스를 구현하거나 상속할 수 있다.
즉, 여러 메서드를 가진 인터페이스를 구현할 때도 사용할 수 있다.
하지만, 람다 표현식은 메서드를 딱 하나만 가지는 함수형 인터페이스만을 구현할 수 있다.
- **익명 클래스**
    - **상태를 유지**하거나 다중 메서드를 구현할 필요가 있는 경우
    - 기존 클래스 또는 인터페이스를 상속하거나 구현할 때
    - 복잡한 인터페이스 구현이 필요할 때
- **람다**
    - **상태를 유지할 필요가 없고**, 간결함이 중요한 경우
    - 단일 메서드만 필요한 간단한 함수형 인터페이스 구현 시
    - 더 나은 성능(이 부분은 미미함)과 간결한 코드가 필요한 경우

##### 람다를 통한 익명 클래스 사용
자바 8부터 함수형 프로그래밍을 지원하기 위한 핵심 기능으로 람다가 도입되었다.
코드 조각을 전달하기 위해서는 클래스를 정의하고 메서드를 만들고 인스턴스를 생성하는 복잡한 과정을 거쳐야한다.

간단하게 클래스나 인스턴스 관계 없이 직접 코드 블럭을 전달하기 위해 람다를 사용한다.
**람다를 사용하면 익명 클래스의 보일러 플레이트 코드를 줄이는** 간결함과 가독성을 높일 수 있다.
(매개변수) -> {본문} 형식으로 람다를 사용한다.
람다는 메서드가 아닌 함수이며, 메서드는 클래스에 속해 있는 함수이고, 함수는 독립적으로 존재한다.
람다도 익명 클래스와 마찬가지로 new 키워드를 사용하지 않고, 클래스가 만들어지면 인스턴스가 생성된다.
```
1. {}와 return 생략이 가능합니다.
   단일 표현식일 경우에만 해당 (int a, int b) -> {return a + b;};
2. 단일 표현식이 아닌경우는 {} 무조건 포함
	MyFunction function3 = (int a, int b) -> { System.out.println("람다 실행"); 
		return a + b; 
	};
3. {} 사용시 반드시 return을 포함합니다. (void 제외)
4. 매개변수 타입 추론 (예측샷)이 가능합니다.
	@FunctionalInterface
	public interface MyFunction {
		int apply(int a, int b);
	}
	// 이렇게 명시가 되어있으면
	(int a, int b) -> a + b; (a, b) -> a + b; 가능
5. 매개변수가 없다면 ()
6. 매개변수가 둘 이상이면 ()
7. 매개변수가 오 로 지 하나!!라면? () 생략가능 !!
```
