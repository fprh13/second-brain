# HTTP 상태코드

---

## 📄 본문
### 1xx — Informational

- **100 Continue**  
    클라이언트가 요청의 일부를 보낸 상태에서 서버가 **나머지 요청을 계속 보내도 된다는 것을 알리는 임시 응답 코드**이다.
    
### 2xx — Success

- **200 OK**  
    클라이언트의 요청이 서버에서 **정상적으로 처리되었을 때** 사용한다.
    
- **201 Created**  
    요청이 성공적으로 처리되어 서버에 **새로운 리소스가 생성되었을 때** 사용한다.
    
- **202 Accepted**  
    서버가 요청을 정상적으로 접수했지만 **아직 처리가 완료되지 않았을 때** 사용한다.  
    비동기 처리 API에서 사용할 수 있다.
    
- **204 No Content**  
    요청은 정상적으로 처리되었지만 **응답 본문으로 반환할 데이터가 없을 때** 사용한다.  
    응답 데이터가 필요 없는 수정이나 삭제 요청 등에 사용할 수 있다.
    
### 3xx — Redirection

- **301 Moved Permanently**  
    요청한 리소스의 URI가 **영구적으로 변경되었을 때** 사용한다.
    
- **302 Found**  
    요청한 리소스가 **일시적으로 다른 URI에 위치하고 있음을 나타낼 때** 사용한다.
    
- **304 Not Modified**  
    클라이언트가 가지고 있는 캐시 이후로 리소스가 **변경되지 않았음을 나타낸다.**  
    클라이언트는 기존에 캐시한 리소스를 계속 사용할 수 있다.
    

### 4xx — Client Error

- **400 Bad Request**  
    잘못된 요청 형식이나 유효하지 않은 요청 값 등으로 인해 서버가 **클라이언트의 요청을 처리할 수 없을 때** 사용한다.
    
- **401 Unauthorized**  
    요청한 리소스에 접근하기 위한 **유효한 인증 정보가 없을 때** 사용한다.
    
- **403 Forbidden**  
    서버가 요청을 이해했지만 클라이언트에게 **해당 리소스에 접근할 권한이 없어 요청을 거부할 때** 사용한다.
    
- **404 Not Found**  
    서버에서 **요청한 리소스를 찾을 수 없을 때** 사용한다.
    
- **405 Method Not Allowed**  
    요청한 URI는 존재하지만 **해당 리소스에서 요청에 사용한 HTTP Method를 지원하지 않을 때** 사용한다.
    
- **409 Conflict**  
    요청 자체는 유효하지만 현재 **리소스의 상태와 충돌하여 요청을 처리할 수 없을 때** 사용한다.  
    중복 데이터 생성이나 동시 수정으로 인한 충돌 등이 대표적인 예이다.
    
- **415 Unsupported Media Type**  
    서버가 요청에 포함된 **미디어 타입을 지원하지 않을 때** 사용한다.  
    예를 들어 JSON만 처리하는 API가 지원하지 않는 `Content-Type`의 요청을 받은 경우이다.
    
- **429 Too Many Requests**  
    클라이언트가 일정 시간 동안 **너무 많은 요청을 보냈을 때** 사용한다.  
    주로 Rate Limit을 초과한 경우 사용한다.
    

### 5xx — Server Error

- **500 Internal Server Error**  
    서버 내부에서 예상하지 못한 오류가 발생하여 **요청을 정상적으로 처리할 수 없을 때** 사용한다.
    
- **502 Bad Gateway**  
    게이트웨이나 프록시 역할을 하는 서버가 **Upstream 서버로부터 유효하지 않은 응답을 받았을 때** 사용한다.
    
- **503 Service Unavailable**  
    서버가 현재 **일시적으로 요청을 처리할 수 없을 때** 사용한다.  
    서버 과부하나 일시적인 서비스 중단 등이 대표적인 경우이다.
