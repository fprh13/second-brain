# 데이터베이스 키

---

## 📄 본문
### 슈퍼키 (Super Key)

> **테이블을 유일하게 식별할 수 있는 모든 키**

- **유일성(O)**
- **최소성(X)**

예를 들어

|id|email|name|
|---|---|---|
|1|[a@test.com](mailto:a@test.com)|홍길동|
|2|[b@test.com](mailto:b@test.com)|김철수|

다음은 모두 슈퍼키이다. (모두 회원을 유일하게 찾을 수 있기 때문)


### 후보키 (Candidate Key)

> **슈퍼키 중 최소성을 만족하는 키**

- **유일성(O)**
- **최소성(O)**

위 예시에서는

```
id
email
```

만 후보키이다.



### 기본키 (Primary Key)

> **후보키 중 대표로 선택한 키**

예를 들어

```sql
id BIGINT PRIMARY KEY
```

대부분의 프로젝트에서는 `id`를 기본키로 사용한다.

#### 특징

- NULL 불가
- 중복 불가
- 테이블당 하나만 존재


### 대체키 (Alternate Key)

> **후보키 중 기본키로 선택되지 않은 키**

예를 들어

```
PK = id
```

이라면

```
email UNIQUE
```

는 대체키이다.


### 외래키 (Foreign Key)

> **다른 테이블의 기본키를 참조하는 키**

```
User
------
id (PK)

Order
------
id
user_id (FK)
```

`user_id`가 외래키입니다.



### 복합키 (Composite Key)

> **여러 컬럼을 합쳐 하나의 키로 사용하는 것**

예)

```
Enrollment

user_id
course_id
```

```sql
PRIMARY KEY(user_id, course_id)
```

### 자연키 (Natural Key)

> **업무적으로 의미가 있는 데이터 자체를 키로 사용하는 것**

예시

- 주민번호
- 이메일
- 사업자번호
- 학번

업무 정책에 따라 변경될 가능성이 있다.


### 대리키 (Surrogate Key)

> **업무 의미 없이 시스템이 만든 키**

예시

```sql
id BIGINT AUTO_INCREMENT
```

또는

```
UUID
```

Spring에서는 보통

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

처럼 사용하는 `id`가 대표적인 대리키이다.


### 키 관계 정리

```
슈퍼키
   └── 후보키
         ├── 기본키
         └── 대체키
```

즉,

```
기본키 ⊂ 후보키 ⊂ 슈퍼키
```

이다.

### 유일성과 최소성

| 키   | 유일성 | 최소성 |
| --- | --- | --- |
| 슈퍼키 | ✅   | ❌   |
| 후보키 | ✅   | ✅   |
| 기본키 | ✅   | ✅   |
| 대체키 | ✅   | ✅   |

### 자연키보다 대리키를 많이 사용한다.
자연키는 이메일처럼 업무 정책에 따라 변경될 수 있다. 이를 기본키로 사용하면 이를 참조하는 모든 테이블에도 변경 영향이 전파된다. 반면 대리키는 업무 의미가 없고 변경되지 않으므로 참조 무결성을 유지하기 쉽고 관리가 편하다. 그래서 실무에서는 대부분 대리키를 기본키로 사용한다.

---

## 📚 참고 및 링크
- **슈퍼키** = 유일하게 식별만 하면 된다.
- **후보키** = 유일하게 식별하면서 **불필요한 컬럼이 하나도 없어야 한다.**
