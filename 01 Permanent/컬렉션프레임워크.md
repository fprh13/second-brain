# 컬렉션프레임워크

---

## 📄 본문
### 배열
배열은 순서가 있고 정적 크기를 가진 자료구조이다.
배열은 인덱스를 사용하기 때문에 삽입, 수정, 조회 시 한 번의 계산으로 원하는 위치에 바로 접근할 수 있어 매우 빠르다.
배열의 인덱스가 아닌 데이터값으로 찾는다면 모든 것을 순회해야해서 배열의 크기 n만큼 연산을 해야한다.

#### point
배열의 인덱스 사용 O(1)
배열의 데이터 값으로 조회하기 위한 순차 검색 O(n)
배열의 마지막을 제외한 추가는 O(n) -> 1 + n or 1/2 + n이다.
n으로 마지막은 남는 공간만 있으면 넣으면 끝나기 때문이다.

##### 배열의 한계
순서가 있고 중복을 허용하지만 크기가 정적으로 고정적이다.
인덱스로 접근해서 조회할 때 가장 빠른 성능을 내는 자료구조이다.
배열의 길이를 동적으로 변경할 수 없고, 모든 데이터를 밀어내고 추가해야되기 때문에 성능이 좋지 않다.

따라서, 배열을 동적으로 변하게 하고 데이터를 추가하기 편한 List가 필요하다.

### 컬렉션 프레임워크
![[../attachments/screenshots/컬렉션프레임워크.png]]

배열과 같이 여러 데이터를 구조화해서 다루는 것을 자료구조라고 합니다.
자바에서는 컬렉션 프레임워크라는 이름으로 다양한 자료구조를 제공합니다.

#### point
##### Collection 인터페이스의 주요 기능
`add(E e)` : 컬렉션에 요소를 추가한다.
`remove(Object o)` : 주어진 객체를 컬렉션에서 제거한다.
`size()` : 컬렉션에 포함된 요소의 수를 반환한다.
`isEmpty()` : 컬렉션이 비어 있는지 확인한다.
`contains(Object o)` : 컬렉션이 특정 요소를 포함하고 있는지 확인한다.
`iterator()` : 컬렉션의 요소에 접근하기 위한 반복자를 반환한다.
`clear()` : 컬렉션의 모든 요소를 제거한다.

###### 정렬 관련 기능
```java
List<Integer> list = new ArrayList<>();
list.add(1);
list.add(2);
list.add(3);
list.add(4);
list.add(5);
Integer max = Collections.max(list); // 최대

Collections.shuffle(list); // 랜덤 섞기

Collections.sort(list); // 정렬 하지만 list.sort(null)추천

Collections.reverse(list); // 반대로 정렬
```

### List
배열은 순서가 있고 중복을 허용하지만 크기가 정적으로 고정된다는 문제점을 가지고 있다. 리스트는 순서가 있고 중복을 허용하지만 크기가 동적으로 변할 수 있다.

즉, 리스트는 배열의 길이를 동적으로 변하게하기 때문에 데이터를 추가하기 편하다.

#### point
##### ArrayList
ArrayList는 순서가 있고 중복을 허용하지만 크기가 동적으로 변하는 자료구조이다.
중간 중간 기존의 크기보다 더 큰 배열을 생성해, 기존 배열 값을 복사하고 기존 리스트 객체의 참조값을 변경하는 식으로 진행한다.

###### ArrayList의 단점
배열의 단점과 동일하다. 데이터를 한칸식 밀어내야한다.
데이터를 앞이나 중간에 추가, 삭제하면 성능이 좋지 않다.
따라서, 데이터를 계속 순서대로 입력하고 순서대로 출력하는 경우에 ArrayList를 주로 사용한다.

###### ArrayList 시간 복잡도
시간 복잡도는 배열과 똑같다. 마지막 데이터의 추가는 항상 O(1)으로 굉장히 빠르다.

###### ArrayList 예시
```java
int[] students = {90, 80, 70, 60, 50};
int total = 0;

for (int i = 0; i < students.length; i++) {
	total += students[i];
}
// -- 위 배열 아래 배열 리스트
List<Integer> students = new ArrayList<>(); 
students.add(90);
students.add(80);
students.add(70);
students.add(60);
students.add(50);
int total = 0;
for (int i = 0; i < students.size(); i++) {
	total += students.get(i); 
}
```

##### LinkedList
배열의 정적인 공간 그리고 처음이나 중간에 데이터를 삽입, 삭제하기 위해 데이터를 미뤄야되는 것을 해결하기 위해 나온 리스트이다.
노드를 만들고 각 노드를 서로 연결하는 방식이다.

연결 리스트에서 사용하는 노드들은 배열이 아니라 단지 다음 노드에 대한 참조가 있을 뿐이다.
인덱스로 원하는 위치의 데이터를 찾으려면 인덱스 숫자 만큼 다음 노드를 반복해야 찾을 수 있어 인덱스를 통한 조회 성능이 좋지 않다.

즉, 특정 노드를 찾기 위해서는 순서대로 모두 순회해야해 성능이 좋지 않지만,
앞 쪽의 데이터를 추가하는 경우에 성능이 좋은 자료구조이다.

###### Java의 LinkedList
자바는 앞 뒤에 모드 노드로 구성된 이중 연결 리스트로 구성이 되어있다.
맨 마지막 노드를 참조하는 변수를 가지고 있어, 뒤에서 데이터를 추가해도 시간복잡도는 O(N)이다.

중간에 데이터를 추가하는 경우에는 ArrayList가 빠르게 때문에 LinkedList는 앞에 데이터를 추가하는 경우가 성능이 좋다.

`lastIndexOf(Object o)`: 리스트에서 지정된 요소의 마지막 인덱스를 반환한다.
`contains(Object o)`: 리스트가 지정된 요소를 포함하고 있는지 여부를 반환한다.
`sort(Comparator<? super E> c)`: 리스트의 요소를 지정된 비교자에 따라 정렬한다.

`iterator()` : 리스트의 요소에 대한 반복자를 반환한다.
`toArray()` : 리스트의 모든 요소를 배열로 반환한다.

### Set
순서가 없고 중복을 허용하는 자료구조이다.
인덱스를 통해 접근 할 수 있다.

#### point
##### 해시 알고리즘
Set의 조회 속도를 O(1)로 줄이기 위해 사용되는 알고리즘이다.
해시 함수를 통해 고유의 정수를 얻어내고 해시인덱스를 통해 인덱스에 저장한다.
충돌된 데이터는 equals()를 통해 하나하나 순회하여 조회합니다.

##### HashSet
해시 자료구조를 사용하여 요소를 저장한다.
요소들은 특정한 순서 없이 저장된다.
해시알고리즘을 통해 추가, 추가 삭제 검색의 평균은 O(1)이다.
```java
Set<Integer> set1 = new HashSet<>(List.of(1, 2, 3, 4, 5));
```

##### LinkedHashSet
Hash Set에 연결 리스트를 추가하여 순서를 유지시킨 자료구조이다.
즉, 추가된 순서대로 요소를 반환한다. 노드 연결 링크를 유지해야하기 때문에, HashSet보다는 약간의 메모리 오버헤드가 존재한다.

따라서, 데이터의 유일성과 순서까지 유지하고자 할 때 적합하다.

##### TreeSet
이진 트리를 개선한 레드 블랙 트리를 사용한 자료구조이다.
요소들은 정렬된 순서로 저장이되며, 또한 순서의 기준을 바꿀 수 있습니다.
삽입 순서가 아닌 원하는 기준으로 저장할 때 사용한다. (ex: 3, 1, 2 -> 1, 2, 3으로 저장하고자 할 때)
따라서, Comparable, Comparator 인터페이스를 구현하여, 정렬 기준을 명시해야한다.
```java
Set<Integer> set = new TreeSet<>(List.of(30, 20, 20, 10, 10));
```

시간복잡도는 O(log n)으로 set 중에 가장느린 조회 성능을 가지고 있다.

##### Tree 구조
트리는 부모 노드와 자식 노드로 구성된다.
가장 높은 노드를 루트라고 부르며, 자식이 2개 까지 올 수 있는 트리가 이진 트리이다.
왼쪽 자식이 작고, 오른 쪽 자식이 더 크게 구성된 구조를 이진 탐색 트리라고하며, 탐색을 할 때 절반 씩 날려가며 진행 할 수 있기 때문에 O(log n)의 시간복잡도를 갖는다.
![[../attachments/screenshots/이진트리.png]]
- 이진 탐색 트리 == 바이너리 서치 트리 == BST

##### 레드 블랙 트리 == RBT
이진 탐색 트리의 문제점을 해결하기 위해 만들어졌다.
이진 탐색 트리 기반으로 진행하기에 이진 탐색 트리의 특징을 가지고 있다.
노드의 자식이 없는 경우 자식을 가리키는 포인터에 리프 노드로 간주되는 NIL을 저장한다.
모든 노드는 빨간색 혹은 검정색으로 색칠하여 연결된 각 노드들의 색이 중복되지 않는다.

##### 해시 인덱스
배열의 인덱스로 사용할 수 있도록 기존의 값으로 계산해낼 수 있는 인덱스를 해시 인덱스라고한다.

예를 들어, 14 나누기 10을 한다고 하면 나머지는 4이다.
그 4를 해시 인덱스라고 할 수 있다.
여기서 10은 배열의 크기이고 통산 그 크기에 맞추어 나머지 연산을 진행한다.
연산이 일어나는곳은 해시함수히다.

##### 해시 함수
해시 함수는 임의의 길이의 데이터를 입력받아 고정된 길이의 해시코드를 출력하는 함수이다.
같은 데이터를 입력하면 항상 같은 해시코드가 출력된다.
다른 데이터를 입력해도 같은 해시코드가 출려될 수 있는데, 이것을 해시 충돌이라고한다.

##### 해시 충돌
같은 해시 인덱스가 나오면 해시 충돌 문제가 일어난다.
따라서, 같은 인덱스에 충돌된 데이터를 배열로 저장해서 해결하고, 조회 시 해당 인덱스 배열의 모든 값을 equals로 비교하여 조회한다.
최악의 경우 O(n)의 성능을 가지지만, 대부분 넓게 퍼져 저장되어 평균 O(1)의 시간 복잡도를 가진다.

```
"BC" → B(66) + C(67) = 133
”AD" → A(65) + D(68) = 133
```

##### 해시 코드
문자를 기반으로 해시를 이용하기 위해 고유한 숫자를 만든다. 만들어진 그 숫자를 해시코드라고한다.
hashCode() 메서드(해시함수)를 사용하면 해시코드를 만들 수 있으며 배열의 인덱스로 사용할 수 있다.
```
a → 97
A → 65
```

해시 인덱스를 사용하는 해시 자료구조는 데이터 추가, 검색, 삭제, 성능이 O(1)로 굉장히 빠르다. 하지만 해시 자료 구조를 사용하려면 정수로된 숫자 값인 해시 코드가 필요하다.
모든 타입을 해시 자료구조에 저장하려면 모든 객체가 숫자 해시 코드를 제공 할 수 있어야하는데, 그것이 Object에 있는 hashCodex()이다.

기본적으로 객체의 참조값을 해시 코드로 사용하기 때문에, 각각의 인스턴스마다 서로 다른 값을 반환한다.
그렇기 때문에, 보통 오버라이딩하여 재정의해야한다.
```java
@Override 
public boolean equals(Object o) {
	if (o == null || getClass() != o.getClass()) return false;
	LoginReqDto that = (LoginReqDto) o;
	return Objects.equals(loginId, that.loginId); 
}
	
 @Override 
 public int hashCode() {
	return Objects.hashCode(loginId);
}
```

##### equals()와 hashCode()를 함께 오버라이딩하라.
데이터가 충돌되어 한 해시 인덱스에 여러 데이터가 저장 되어있는 상태에 어떤 특정 데이터를 조회하기 위해 접근한다면, 모든 데이터를 하나하나 비교하여 찾아야한다.
따라서 hashCode()뿐만 아니라 equals()도 함께 오버라이딩해야한다.

##### Set 인터페이스 주요 기능
`add(E e)` : 지정된 요소를 set에 추가한다. (이미 존재하는 경우 추가하지 않음)
`addAll(Collection<? extends E> c)` : 지정된 컬렉션의 모든 요소를 set에 추가한다.
`contains(Object o)` : set가 지정된 요소를 포함하고 있는지 여부를 반환한다.
`containsAsll(Collection<?> c)` : 세트가 지정된 컬렉션의 모든 요소를 포함하고 있는지 여부를 반환한다.
`remove(Object o)` : 지정된 요소를 set에서 제거한다.
`removeAll(Collection<?> c)` : 지정된 컬렉션에 포함된 요소를 set에서 모두 제거한다.
`retainAll(Collection<?> c)` : 지정된 컬렉션에 포함된 요소만을 유지하고 나머지 요소는 set에서 제거한다.
`clear()` : set에서 모든 요소를 제거한다.
`size()` : set에 있는 요소의 수를 반환한다.
`isEmpty()` : set이 비어있는지 여부를 반환한다.
`iterator()` : set의 요소에 대한 반복자를 반환한다.
`toArray()` : set의 모든 요소를 배열로 반환한다.
`toArray(T[] a)` : set의 모든 요소를 지정된 배열로 반환한다.

### Map
키 - 값 쌍을 저장하는 자료구조이다.
순서를 보장하지 않고 키는 중복되지 않는 구조이다. (값은 중복 가능)
키를 통해서 데이터를 빠르게 검색할 수 있다.

#### point
##### Map의 구성
키 값으로 저장되어, Entry라는 객체로 한 쌍을 관리한다. 

##### HashMap
해시를 사용하여 요소를 Map에 저장한다.
순서를 보장하지 않으며, 삽입, 삭제 검색 작업에 해시 자료구조를 사용해 평균 O(1)이라는 시간복잡도를 가진다.
작동원리는 HashSet과 거의 유사하다.

##### LinkedHashMap
키 - 값 쌍을 저장하는 자료구조이다.
Map 데이터의 입력 순서를 보장하며, 입력 순서를 링크로 유지하기 때문에 메모리 오버헤드가 존재한다.

##### TreeMap
레드 블랙 트리를 기반으로한 구조이며, 정렬된 순서를 comparator를 통해 보장한다.
get(), put(), remove()는 모두 O(log n) 시간복잡도를 가진다.

##### Map.of() vs new HashMap<>()
Map을 생성할 때 Map.of()를 사용하면 편리하게 Map을 생성할 수 있지만, 불변으로 생성되어 내용을 변경할 수 없다.
```java
// Map.of vs new HashMap<>()
Map<String, Integer> map1 = Map.of("A", 1, "B", 2, "C", 3);
Map<String, Integer> map2 = Map.of("B", 4, "C", 5, "D", 6);

Map<String, Integer> map1 = new HashMap<>(); map1.put("A", 1);

// 2차원 배열을 Map으로 변경
String[][] productArr = {{"Java", "10000"}, {"Spring", "20000"},
{"JPA", "30000"}};

// 주어진 배열로부터 Map 생성
Map<String, Integer> productMap = new HashMap<>();

for (String[] product : productArr) {
productMap.put(product[0], Integer.valueOf(product[1]));
}

// Map의 모든 데이터 출력
for (String key : productMap.keySet()) {
System.out.println("제품: " + key + ", 가격: " +
productMap.get(key));
```

##### Map 인터페이스 주요 메서드
`put(K key, V value)` : 지정된 키와 값을 Map에 저장한다. (같은 키가 있으면 값을 변경)
`putAll(Map<? extends K, ? extends V>)` : 지정된 Map의 모든 맵핑을 현재 앱에 복사한다.
`putIfAbsent(K key, V value)` : 지정된 키가 없는 경우에 키와 값을 Map에 저장한다. (Absent: 결석한)
`get(Object key)` : 지정된 키에 연결된 값을 반환한다.
`getOrDefault(Object key, V defaultValue)` : 지정된 키에 연관된 값을 반환한다. 키가 없는 경우 defaultValue로 지정한 값을 대신 반환한다.
`remove(Object key)` : 지정된 키와 그에 연결된 값을 맵에서 제거한다.
`clear()` : Map에서 모든 키와 값을 제거한다.
`containsKey(Object key)` : Map이 지정된 키를 포함하고 있는지 여부를 반환한다.
`containsValue(Object value)` : Map이 하나 이상의 키에지정된 값을 연결하고 있는지 여부를 반환한다.
`keySet()` : Map의 키들을 Set 형태로 반환한다.
`values()` : Map의 값들을 Collection 형태로 반환한다.
`entrySet()` : Map 키 - 값 쌍을 `Set<Map.Entry<K, V>>` 형태로 반환한다.
`size()` : Map에 있는 키 - 값 쌍의 개수를 반환한다.
`inEmpty()` : Map이 비어 있는지 여부를 반환한다.


### Stack
스택 리포(LIFO) 후입선출 방식으로 나중에 들어온 요소가 먼저 나오는 자료구조입니다.
push()를 통해 요소를 넣고, pop()을 통해 요소를 빼낸다.
Vector, Stack는 레거시하기에 Deque를 이용해서 사용해야한다.

### Queue
큐 삐뽀(FIFO) 선입선출 방식으로 먼저 들어간 요소가 먼저 나오는 자료구조이다.
offer()를 통해 요소를 넣고 poll()을 통해 요소를 빼냅니다.

#### point
##### 우선 순위 큐  PriorityQueue
우선 순위 큐는 들어간 순서에 상관 없이 우선 순위가 높은 데이터를 먼저 꺼내기 위해서 나온 자료구조이다.
배열, LinkedList, Heap으로 구현이 가능하며, 일반적으로는 완전 인진 트리 형태로 Heap을 이용하여 구현한다.

###### Heap
최댓값이나 최솟값을 찾아내는 연산을 빠르게 하기 위해 나온 자료구조이다.
각 노드의 키 값이 자식의 키 값 보다 작지 않거나(최대힙) 그 자식의 키값 보다 크지 않는(최소힙) 형태의 완전 이진 트리이다.

### Deque
데크는 일반적인 큐와 스택의 기능을 모두 포함하고 있다.
데크의 대표적인 구현체로는 ArrayDeque, LinkedList가 있으며, 일반적으로 ArrayDeque가 빠르다.

```java
Deque<Integer> deque = new ArrayDeque<>();
//Deque<Integer> deque = new LinkedList<>();
// 데이터 추가
deque.offerFirst(1);
System.out.println(deque);
deque.offerFirst(2);
System.out.println(deque);
deque.offerLast(3);
System.out.println(deque);
deque.offerLast(4);
System.out.println(deque);

// 다음 꺼낼 데이터 확인(꺼내지 않고 단순 조회만)
System.out.println("deque.peekFirst() = " + deque.peekFirst());
System.out.println("deque.peekLast() = " + deque.peekLast());
// 데이터 꺼내기
System.out.println("pollFirst = " + deque.pollFirst());
System.out.println("pollFirst = " + deque.pollFirst());
System.out.println("pollLast = " + deque.pollLast());
System.out.println("pollLast = " + deque.pollLast());


--- 위는 큐 아래는 스택
// 데이터 추가
deque.push(1);
deque.push(2);
deque.push(3);
System.out.println(deque)

// 다음 꺼낼 데이터 확인(꺼내지 않고 단순 조회만)
System.out.println("deque.peek() = " + deque.peek());
// 데이터 꺼내기
System.out.println("pop = " + deque.pop());
System.out.println("pop = " + deque.pop());
System.out.println("pop = " + deque.pop());
```

### Iterable
개발자가 편리하고 일관된 방법으로 자료구조를 순회 할 수 있도록 제공하는 인터페이스이다.
각 구현체에 맞는 Iterator를 구현해 두어서 모든 컬렉션을 순회할 수 있다.

#### point
##### Iterator(반복자) 디자인 패턴
객체 지향 프로그래밍에서 컬렉션의 요소들을 순회할 때 사용되는 디자인 패턴이다.
이 패턴은 컬렉션의 내부 표현 방식을 노출시키지 않으면서 그 안의 각 요소에 순차적으로 접근할 수 있게 해준다.
복잡성을 줄이고 재사용성을 높인다는 장점을 가지고 있다.

### Comparable
객체의 기본 정렬 방법은 객체에 Comparable을 구현해서 정의합니다.
이름 그대로 비교할 수 있는 정렬 방법을 가진 객체로 만들 수 있으며, 
이 경우 정렬 메서드는 별도로 구현한 정렬 메서드가 우선권을 가진다.
String, Integer는 Comparable을 구현해 두었다.
```java
public class IdComparator implements Comparator<MyUser> {
@Override
public int compare(MyUser o1, MyUser o2) {
	return o1.getId().compareTo(o2.getId());
	}
}
```

### 자료구조 선택법

##### List
순서가 중요하고 중복이허용되는경우 사용한다.
일반적인 상황에서는 ArrayList를 사용하고
추가, 삭제가 앞쪽에서 빈번한 경우 LinkedList를 사용하자.

##### HashSet
중복을 허용하지 않고 순서가 중요하지 않는 경우 HashSet을 사용한다.
순서를 유지해야한다면, LinkedHashSet을 사용하며,
정렬된 순서가 필요하다면 TreeSet을 사용하자.

##### Map
요소의 키값을 쌍으로 저장하려는 경우 HashMap을 사용한다.
순서를 유지해야한다면 LinkedHashMap을 사용하며,
정렬된 순서가 필요하다면 TreeMap을 사용하자.

##### Queue, Deque
요소를 처리하기 전에 보관해야하는 경우에는 모두 ArrayDeque를 사용한다.
우선 순위에 따라 요소를 처리해야한다면, PriorityQueue를 고려한다.
