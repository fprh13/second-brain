# OSI 7계층

---

## 📄 본문
### OSI 7 계층

OSI 7계층은 네트워크에서 데이터가 통신하는 과정을 7개의 계층으로 나눈 표준 모델이다.

각 계층은 특정 역할을 담당하며, 상위 계층은 하위 계층이 제공하는 기능을 이용하여 통신한다.

네트워크 통신 과정을 계층별로 분리함으로써 각 계층의 역할을 명확하게 구분하고, 특정 계층에서 문제가 발생했을 때 원인을 파악하기 쉽게 한다.

송신 측에서는 데이터를 7계층에서 1계층 방향으로 전달하면서 각 계층에 필요한 정보를 추가하는 캡슐화(Encapsulation)가 이루어지고, 수신 측에서는 1계층에서 7계층 방향으로 전달하면서 이를 제거하는 역캡슐화(Decapsulation)가 이루어진다.

#### point
##### 7계층 - 응용 계층 (Application)

- 사용자와 가장 가까운 계층
- 응용 프로그램이 네트워크 서비스를 이용할 수 있도록 제공
- 프로토콜: HTTP, HTTPS, FTP, SMTP, DNS

##### 6계층 - 표현 계층 (Presentation)

- 데이터 형식 변환
- 암호화/복호화
- 압축/해제
- 예시: UTF-8 인코딩, SSL/TLS 암호화

##### 5계층 - 세션 계층 (Session)

- 통신 연결 생성, 유지, 종료
- 세션 동기화 및 복구
- 예시: 로그인 세션 관리

##### 4계층 - 전송 계층 (Transport)

- 종단 간(End-to-End) 데이터 전송
- 신뢰성 보장
- 흐름 제어, 오류 제어
- 프로토콜: TCP, UDP

##### 3계층 - 네트워크 계층 (Network)

- IP 주소 기반 통신
- 최적 경로 탐색(라우팅)
- 프로토콜: IP, ICMP

##### 2계층 - 데이터 링크 계층 (Data Link)

- 같은 네트워크 내 장치 간 통신
- MAC 주소 사용
- 프레임 단위 전송
- 오류 검출(CRC)
- 예시: Ethernet, Wi-Fi

##### 1계층 - 물리 계층 (Physical)

- 실제 전기 신호, 광 신호 전송
- 케이블, 허브, 리피터 등
- 비트(Bit) 단위 전송

### 실제 데이터 전송 흐름
카카오톡과 같은 메신저에서 `"안녕"`이라는 메시지를 전송한다고 가정하면 데이터는 OSI 계층을 따라 아래 방향으로 전달된다.

#### 송신 측 - 캡슐화

사용자가 입력한 `"안녕"`이라는 데이터는 상위 계층에서 하위 계층으로 내려가면서 각 계층에서 통신에 필요한 정보가 추가된다.

```
7계층 - Application
"안녕"이라는 애플리케이션 데이터 생성
        ↓
6계층 - Presentation
데이터 인코딩, 암호화 등의 처리
        ↓
5계층 - Session
통신 세션의 설정 및 유지
        ↓
4계층 - Transport
TCP Header 추가
→ Segment
        ↓
3계층 - Network
IP Header 추가
→ Packet
        ↓
2계층 - Data Link
Ethernet/Wi-Fi Header 등의 정보 추가
→ Frame
        ↓
1계층 - Physical
0과 1의 Bit를 실제 신호로 전송
```

이처럼 데이터가 하위 계층으로 내려가면서 각 계층에 필요한 정보를 추가하는 과정을 **캡슐화(Encapsulation)**라고 한다.

데이터 단위는 다음과 같이 변화한다.

```
Data
 ↓
Segment
 ↓
Packet
 ↓
Frame
 ↓
Bit
```

#### 실제 네트워크를 통한 전달

스마트폰이 Wi-Fi에 연결되어 있다면 데이터는 대략 다음과 같은 경로를 통해 목적지 서버로 전달된다.

```
스마트폰
   ↓
Wi-Fi 공유기
   ↓
통신사 네트워크
   ↓
여러 라우터
   ↓
인터넷
   ↓
목적지 서버
```

이 과정에서 **IP 주소는 최종 목적지까지 패킷을 전달하기 위한 주소**로 사용된다.
라우터는 패킷의 목적지 IP 주소를 확인하여 다음으로 전달할 경로를 결정한다.
반면 **MAC 주소는 현재 연결된 네트워크 구간에서 다음 장치로 프레임을 전달하기 위해 사용**된다.
따라서 라우터를 거쳐 다른 네트워크로 이동할 때 2계층의 프레임 정보는 변경될 수 있다.

#### 수신 측 - 역캡슐화

목적지 서버에 데이터가 도착하면 송신 측과 반대 방향으로 처리된다.

```
1계층 - Physical
Bit 수신
        ↓
2계층 - Data Link
Frame 처리
        ↓
3계층 - Network
Packet의 IP 정보 처리
        ↓
4계층 - Transport
Segment의 TCP 정보 처리
        ↓
5~7계층
상위 계층에서 데이터 처리
        ↓
"안녕"
```

이처럼 수신 측에서 각 계층의 정보를 확인하고 제거하면서 원래 데이터를 복원하는 과정을 **역캡슐화(Decapsulation)**라고 한다.

**송신 측**

```
Data → Segment → Packet → Frame → Bit
```

**수신 측**

```
Bit → Frame → Packet → Segment → Data
```
