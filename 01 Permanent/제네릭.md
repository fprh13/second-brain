# 제네릭

---

## 📄 본문
### 제네릭
타입을 미리 결정하지 않고 실제 사용하는 생성 시점에 타입을 결정하는 것이다.
타입 안정성과 코드 재사용성을 높힌다.
컴파일 시점에 타입에 대한 에러를 확인할 수 있어서 안정성이 높다.
상한 타입 매개변수 제한으로 들어올 객체의 상한을 제한할 수 있다.

#### point
Object를 사용하면, 타입 캐스팅 시 오류가 발생할 수 있다.
따라서, 타입 안정성이 높은 제네릭을 사용한다.

### 제네릭 타입
```
GenericBox<T>
```
클래스나 인터페이스를 정의할 때 타입 매개 변수를 사용하는 것을 말한다.
제네릭 클래스, 제네릭 인터페이스를 모두 합쳐서 제네릭 타입이라고 한다.

#### point
제네릭 타입 매개 변수 명명 관례
- E - Element (컬렉션에 저장되는 요소, `List<E>`)
- K - Key
- V - Value
- N - Number
- T - Type
- S,U,V etc. - 2nd, 3rd, 4th types


##### 타입 매개변수
제네릭 타입이나 메서드에서 사용되는 변수로 실제 타입으로 대체된다.
```
GenericBox<T>
```
 의 T를 타입 매개 변수라고한다.

##### 타입 인자
제네릭 타입이나 메서드에서 사용되는 변수로 실제타입으로 대체된다.
```
GenericBox<Integer>
```
의 Integer가 타입인자이다.
기본형으로는 사용할 수 없고 래퍼 클래스만 사용할 수 있다.

### 타입 매개변수 상한
```
GenericBox<T extends Animal>
```
처럼 진행하게 되면 타입인자로 들어올 수 있는 그 자식만 받을 수 있도록 타입 메개 변수 T의 상한이 특정 객체가 되는 것이다.
타입 안정성을 지키면서 상위 타입의 원하는 기능까지 사용할 수 있고 코드 재사용성과 타입 안정성이라는 두마리 토끼를 동시에 잡을 수 있다.

### 제네릭 메서드
클래스 단위가 아니라 메서드 단위로 제네릭을 도입할 때 사용된다.
제네릭 타입보다 제네릭 메서드가 우선순위가 높다.
제네릭 메서드도 상한 제한이 가능하다.

#### point
참고 코드
```java
public class ComplexBox<T extends Animal> {

private T animal;

public void set(T animal) {
	this.animal = animal;
}

public <T> T printAndReturn(T t) {
	System.out.println("animal.className: " +
	animal.getClass().getName());
	System.out.println("t.className: " + t.getClass().getName());
	// t.getName(); // 호출 불가 메서드는 <T> 타입이다. <T extends Animal> 타입이아니다.
return t;
}
}
```

### 와일드카드
제네릭 타입을 조금 더 편리하게 사용할 수 있도록 하는 것이다.
?를 이용해서 정의한다.
?만 두면 비제한 와일드카드로 작동된다.
extends 키워드를 통해 상한을 두며, super 키워드를 통해 하한을 둔다.
타입 인자를 결정 할 필요가 없어서 간단하다.

#### point
제네릭 메서드에는 타입 매개변수가 존재하고 그리고 특정 시점에 타입 매개변수에 타입 인자를 전달해서 타입을 결정해야한다.
하지만 와일드 카드는 제네릭 타입을 받을 수 있는 매개변수가 하나 있는 뿐이라 간단하다.

### 타입 이레이저
제네릭은 컴퍼아리 시점에 타입 안정성을 검사하기 위해 사용되며, 컴파일 과정에서 제네릭의 타입 정보가 제거되는 타입 이레이저가 적용된다.

컴파일러는 타입 매개변수를 Object 또는 상한으로 치환하기 때문에
런타임에는 T와 같은 타입 매개변수를 별도의 런타임 타입으로 유지하지 않는다.

#### point
상한 제한이 없는 타입 매개변수 T는 Object이고 상한은 상한 객체로 변환한다.
때문에 타입 매개션수에 instanceOf가 허용되지 않는다.
그리고 타입 매개변수에는 new T를 허용하지 않는다.
