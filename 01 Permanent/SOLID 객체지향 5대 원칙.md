# SOLID 객체지향 5대 원칙

---

## 📄 본문

### SOLID
SOLID 원칙이란 객체지향 설계에서 지켜줘야 할 5개의 소프트웨어 개발 원칙이다.
SOLID 원칙을 적용하면 코드를 화장하고 유지 보수 관리하기 더 쉬워지며, 불필요한 복잡성을 제거해 리펙토링에 소요되는 시간을 줄임으로 써 프로젝트 개발의 생산성을 높일 수 있다.
1. **단일 책임 원칙** (Single Responsibility Principle)
2. **개방 폐쇄 원칙** (Open Close Principle)
3. **리스코프 치환 원칙** (Liscov Substitution Principle)
4. **인터페이스 분리 원칙** (Interface Sergregation Principle)
5. **의존성 역전 원칙** (Dependency Inversion Principle)

### SRP 단일 책임의 원칙
하나의 객체는 반드시 하나의 책임만을 가져야 한다는 원칙이다.
만일 하나의 클래스에 기능이 여러개 있다면 기능 변경이 일어났을 때 수정해야할 코드가 많아진다.
따라서, SRP 원칙을 따름으로써 변경의 전파를 줄일 수 있다.

#### point
프로그램의 유지 보수성을 높이기 위한 설계 기법

### OCP 개방폐쇠의 원칙
확장에는 열려 있고(Open), 변경에는 닫혀 있어야(Closed) 한다는 설계 원칙이다.
즉, 새로운 기능이나 요구사항이 추가되었을 때 기존 코드의 수정을 최소화하면서 새로운 구현을 추가하여 기능을 확장할 수 있도록 설계하는 것을 의미한다.

#### point
OCP 원칙은 추상화 사용을 통한 관계 구축을 권장한다는 의미

### LSP 리스코프 치환의 원칙
자식객체는 부모객체를 완전히 대체할 수 있어야한다는 원칙이다.
자식객체가 부모의 메서드를 사용해도 동작이 의도대로 흘러가야 하는 것을 의미한다.

#### point
LSP 다형성 원리를 이용하기 위한 원칙

### ISP 인터페이스 분리의 원칙
인터페이스 분리 원칙(ISP)은 클라이언트가 자신이 사용하지 않는 메서드에 의존하지 않도록 인터페이스를 사용 목적과 역할에 따라 분리해야 한다는 설계 원칙이다.

즉, 하나의 큰 인터페이스에 여러 책임을 포함하기보다 클라이언트가 필요로 하는 기능을 기준으로 인터페이스를 분리하여, 각 클라이언트가 자신에게 필요한 인터페이스에만 의존하도록 하는 것을 목표로 한다.

#### point
한번 인터페이스를 분리하여 구성해놓고 나중에 무언가 수정사항이 생겨서 또 인터페이스들을 분리하는 행위를 가하지 말아야한다. (인터페이스를 한번 구성했다면, 왠만해선 변경하면 안된다는 정책의 개념)

### DIP 의존성 역전 원칙
구체적인 구현이 아닌 추상화에 의존해야 한다는 설계 원칙이다.

즉, 의존 관계를 맺을 때 변경 가능성이 높은 구체적인 구현에 직접 의존하기보다, 상대적으로 변경에 안정적인 추상화에 의존하도록 설계하는 것을 의미한다.

#### point
DIP 의존성 역전 원칙의 지향점은 각 클래스간의 결합도(coupling)을 낮추는 것이다.
