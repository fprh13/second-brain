# 레디스의 의문점 정리

---

## 📄 요약

### Redis란?

> Redis는 데이터를 디스크가 아닌 메모리(RAM)에 저장하는 인메모리 Key-Value 저장소이다.

### Redis는 왜 빠른가?

> 디스크 접근 없이 RAM에서 직접 데이터를 조회하기 때문이다.

### Redis가 재시작 후에도 데이터가 남는 이유는?

> RDB Snapshot 또는 AOF 영속화 파일을 통해 디스크에 저장한 후 재시작 시 복구하기 때문이다.

### Replication이란?

> 동일한 데이터를 Replica 노드에 복제하여 장애 대응과 읽기 부하 분산을 수행하는 방식이다.

### Sharding이란?

> 데이터를 여러 Redis 노드에 분산 저장하여 저장 용량과 처리량을 확장하는 방식이다.

### Redis Cluster란?

> 여러 Redis 노드를 묶어 샤딩과 복제를 자동으로 제공하는 분산 Redis 환경이다.

---

## 📄 본문
복습용으로는 아래 정도로 정리해두면 좋을 것 같아.

### 1. Redis란?

Redis는 대표적인 **인메모리(Key-Value)*데이터 저장소**이다.

```text
MySQL
→ 디스크 중심

Redis
→ 메모리(RAM) 중심
```

데이터를 RAM에 저장하기 때문에 매우 빠르다.

---

### 2. 인메모리라는 뜻

인메모리란 데이터를 디스크가 아니라 RAM에 저장한다는 의미이다.

예를 들어:

```redis
SET user:1 yeongmu
```

를 실행하면

```text
RAM
└─ user:1 = yeongmu
```

형태로 저장된다.

---

### 3. Redis는 클라우드인가?

아니다.

"인메모리"와 "클라우드"는 다른 개념이다.

### 인메모리

어디에 저장하는가?

```text
RAM
```

### 클라우드

어디에서 실행하는가?

```text
AWS
GCP
Azure
내 PC
```

---

예를 들어 AWS에서 Redis를 사용하면

```text
AWS 서버
 └─ Redis
      ↓
   AWS 서버 RAM 사용
```

이다.

---

### 4. 내가 Docker Redis를 실행하면

현재 네 상황:

```text
맥북
 └─ Docker
      └─ Redis
```

Redis가 사용하는 메모리는

```text
맥북 RAM
```

이다.

즉

```text
SET user:1 yeongmu
```

하면 실제로 맥북 RAM에 저장된다.

---

### 5. Redis는 왜 안 날아가나?

원래 RAM은 휘발성이다.

```text
전원 OFF
↓
RAM 데이터 소멸
```

하지만 Redis는 영속화 기능을 제공한다.

---

### 6. RDB 방식

Snapshot 방식

특정 시점마다

```text
RAM
↓
dump.rdb
```

파일로 저장한다.

재시작 시

```text
dump.rdb
↓
RAM 복구
```

한다.

---

### 7. AOF 방식

모든 쓰기 명령을 기록한다.

예시:

```redis
SET user:1 kim
DEL user:2
```

↓

```text
appendonly.aof
```

에 기록

재시작 시 명령을 다시 실행하여 복구한다.

---

### 8. Docker Volume 역할

Volume은 Redis 데이터 자체가 아니라

```text
dump.rdb
appendonly.aof
```

파일을 보관하는 장소이다.

```text
Redis RAM
↓
RDB/AOF 파일
↓
Docker Volume
↓
SSD/HDD
```

---

### 9. Redis는 왜 빠른가?

디스크 접근보다 RAM 접근이 훨씬 빠르기 때문이다.

```text
MySQL
RAM → SSD

Redis
RAM → RAM
```

---

### 10. Redis는 램을 많이 먹나?

학습용 수준은 거의 안 먹는다.

예시:

```text
Chrome
1~3GB

IntelliJ
1~2GB

Docker
1~2GB

Redis
몇 MB ~ 수십 MB
```

보통 로컬 Redis는 큰 부담이 없다.

---

### 11. Replication (복제)

같은 데이터를 복사한다.

```text
Master
 └─ user:1

Replica
 └─ user:1
```

목적:

- 장애 대응
    
- 읽기 부하 분산
    

용량 증가는 없음

---

### 12. Sharding (샤딩)

데이터를 나눠 저장한다.

```text
Redis A
 └─ user:1

Redis B
 └─ user:2

Redis C
 └─ user:3
```

목적:

- 저장 용량 증가
    
- 처리량 증가
    

---

### 13. 왜 샤딩이 필요한가?

예를 들어

```text
Redis 1대
RAM 64GB
```

보다

```text
Redis 8대
RAM 8GB × 8
```

를 선호하기도 한다.

이유:

- 장애 범위 감소
    
- CPU 증가
    
- 수평 확장 가능
    
- 대형 Redis 운영 부담 감소
    

---

### 14. Cluster란?

가장 중요한 개념.

### 오해

```text
Redis 하나를 쪼개는 것
❌
```

### 실제

```text
Redis 여러 개를 묶는 것
⭕
```

예시:

```text
Redis A
Redis B
Redis C
```

를 하나의 Redis처럼 사용

---

### 15. Redis Cluster 구조

```text
Master A ← Replica A
Master B ← Replica B
Master C ← Replica C
```

특징:

- 샤딩 O
    
- 복제 O
    
- 자동 Failover O
    

---

### 16. Redis Cluster 동작

애플리케이션은

```java
redisTemplate.opsForValue()
             .set("user:123", value);
```

만 호출

그러면 Cluster가

```text
user:123
↓
해시 계산
↓
Master B 저장
```

을 자동 수행

개발자는 어느 Redis에 저장되는지 신경 쓰지 않는다.
