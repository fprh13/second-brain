# 유튜브 다중조인 N+1 강의 오류 발견 및 해결 방법

---

## 📄 요약
유튜브의 개발자 유미님의 N+1 강의를 보던 중 논리적 오류가 있다고 판단되어 정리합니다.

---

## 📄 본문

### 의문을 갖게 된 댓글

#### 질문자(시청자)
```text
Q:다름이 아니라 fetch + in조인으로 조회 시 batch 사이즈를 설정한 후 조회하면 city쪽 카타시안 곱은 발생 하는 것 같은데 강의에서는 DISTINCT가 없어 쿼리 날리셨는데 어떻게 해결하셨을까요..
```

#### 답변자(강사)
```text
A: 우선 2개의 OneToMany에서 한쪽은 LEFT JOIN FETCH 나머지는 Batch IN절을 진행할 경우, "a" fetch join "b"(one쪽) in "c" 첫번째로 a와 b는 left join fetch로 단 1개의 쿼리가 날라가며 어차피 단일 OneToMany이기 때문에 카티션곱은 없습니다. (조회시는 중복이 있지만, 단일 OneToMany 마인드라 Set이 자동으로 진행 됩니다) 여기에 대해 두번째 쿼리로 in절에 의해 c쪽이 1개 이상 날라가게 되는데, 이미 b가 위에서 set처리 되었기 때문에 따로 distinct 처리하지 않아도 카티션 곱에 대한 문제는 걱정하제 않으샤도 됩니당!!
```

#### 나의 생각
```text
A: 카타시안 곱은 아니지만 Row의 곱이 일어나는 상황입니다.
해당 문제를 제기하셨다면, Distinct부분이 아니라 먼저 JOIN 절을 보셔야합니다.
현재 강사님이 작성하신 JPQL을 보시면, 레이지로딩된 종교 컬렉션을 Fetch없이 진행하셨습니다.
컬렉션이 초기화되지 않고 프록시 상태로 있는것인데요.
즉, 종교로 인한 조인 연산이 발생하고, 이후에 Batch + In절로 가져오는 방식입니다.

따라서, 불필요한 Row곱을 줄이기 위해서는, 종교의 LEFT JOIN을 제거하시면 됩니다.
(Distinct는 다른 문제지만 부모 엔티티에 대한 중복데이터가 생김으로 진행하는것이 좋다고 생각합니다.)
```

### 배경
#### 도메인 구조

```text
Country (1)
 ├─ City (N)
 └─ Religion (N)
```

두 개의 `@OneToMany` 컬렉션이 존재합니다.

---

#### 대상 코드

```java
@Query("""
    SELECT co
    FROM CountryEntity co
    LEFT JOIN FETCH co.cityEntities c1
    LEFT JOIN co.religionEntities re
""")
List<CountryEntity> findAllFetch();
```

---

### 강사 코드의 실제 동작 분석

#### 1. SQL 실행

이 JPQL은 다음과 같은 SQL로 변환됩니다.

```sql
select ...
from country co
left join city c1
  on c1.country_id = co.id
left join religion re
  on re.country_id = co.id
```

즉:

```text
cityEntities → fetch join
religionEntities → 일반 join
```

---

#### 2. 결과 row 형태

예시 데이터:

```text
한국
- city: 서울, 부산
- religion: 불교, 기독교, 천주교
```

SQL 결과:

```text
한국 - 서울 - 불교
한국 - 서울 - 기독교
한국 - 서울 - 천주교
한국 - 부산 - 불교
한국 - 부산 - 기독교
한국 - 부산 - 천주교
```

즉:

```text
city 개수 × religion 개수
```

만큼 row가 생성됩니다.

---

#### 3. 엔티티 매핑 결과

최종 반환 타입:

```java
List<CountryEntity>
```

JPA는 다음과 같이 처리합니다.

```text
CountryEntity는 1차 캐시에서 식별자로 중복 제거
cityEntities는 fetch join으로 즉시 로딩
religionEntities는 초기화되지 않음
```

결과 상태:

```text
한국.cityEntities = [서울, 부산]
한국.religionEntities = 아직 로딩 안됨 (지연 로딩 상태)
```

---

#### 4. 이후 컬렉션 접근 시

```java
co.getReligionEntities()
```

호출 시:

```sql
select ...
from religion
where country_id in (?, ?, ...)
```

BatchSize 설정이 있다면 IN절로 조회됩니다.

---

### 내가 제기한 문제점

#### 1. 조인 비용 낭비

```text
첫 번째 쿼리에서 이미 religion까지 join 수행
하지만 컬렉션에는 반영되지 않음
```

즉, 조인은 했지만 결과는 사용하지 않음

---

#### 2. row 증가

```text
city × religion 만큼 row 증가
```

이는 카티션 곱과 유사한 형태의 데이터 증가입니다.

---

#### 3. 추가 쿼리 발생

```text
이미 join 했음에도 불구하고
religionEntities 접근 시 다시 조회 발생
```

---

### 올바른 접근 방식

```java
@Query("""
    SELECT DISTINCT co
    FROM CountryEntity co
    LEFT JOIN FETCH co.cityEntities
""")
List<CountryEntity> findAllFetch();
```

```text
cityEntities → fetch join
religionEntities → BatchSize + IN절 조회
```

### 최종 결론

```text
1. OneToMany 컬렉션은 fetch join을 1개만 사용하는 것이 안전하다

2. fetch join하지 않을 컬렉션은 JPQL에서 아예 제거하는 것이 좋다

3. 일반 join은 컬렉션을 채우지 않으며, 조인 비용만 발생시킨다

4. 현재 코드에서 religionEntities join은 불필요한 비용을 발생시킨다

5. 해당 구조는
   fetch join 1개 + BatchSize(IN절)
   전략으로 변경하는 것이 바람직하다
```
