# IntelliJ AI 개발 환경 세팅

---

## 📄 요약
IntelliJ AI 개발 환경 재정립 속도는 JetBrains, 품질은 Gemini, 확장성은 Codex

---

## 📄 본문

### 기존 문제: 하나의 AI로 모든 것을 해결하려 했던 구조

초기에는 JetBrains AI Assistant를 중심으로 개발을 진행했습니다. IntelliJ와의 통합이 뛰어나고, 별도의 설정 없이 바로 사용할 수 있다는 점이 매력적이었습니다.

하지만, 코드 생성 품질이 아쉬웠습니다.  
단순 자동완성이나 리팩토링은 가능했지만, 서비스 로직이나 테스트 코드 작성에서는 **맥락을 깊게 이해하는 능력이 부족**하게 느껴졌습니다.

### 과정에서 겪은 문제: Gemini 도입 이후의 혼란

이 문제를 해결하기 위해 Gemini Code Assist를 도입했습니다.

확실히 달라진 점은 있었습니다.

- 코드 생성 품질이 높아짐
    
- 주석 기반 로직 생성이 자연스러움
    
- 테스트 코드 작성 시 구조 이해도가 올라감
    

하지만 라인 단위 자동완성에서는 속도가 느리게 느껴졌습니다.  
**JetBrains 대비 반응 속도가 느리고 흐름이 끊기는 느낌**이 들었습니다.

### 문제의 본질: 도구 선택이 아니라 역할 설계 문제

여기서 깨달은 핵심은 다음이었습니다.

> 하나의 AI로 모든 문제를 해결하려는 접근이 잘못된 것이다.

AI 도구마다 강점이 다르기 때문에,  
**“어떤 도구를 쓰느냐”보다 “어떻게 나누느냐”가 중요했습니다.**

### 최종 결론: 역할 기반 3단 구조

최종적으로 다음 구조로 정리했습니다.

#### 속도: JetBrains AI Assistant + IntelliJ 기본 completion

- 라인 단위 자동완성
    
- 반복 코드 작성
    
- 메서드 체이닝, import, 타입 추천
    

손을 빠르게 움직이게 하는 역할

#### 품질: Gemini Code Assist

- 서비스 로직 생성
    
- 테스트 코드 작성
    
- 리팩토링
    
- 코드 설명
    

빠르게 머리를 대신 써주는 역할

#### 확장성: Codex CLI

- 여러 파일 수정
    
- 구조 리팩토링
    
- 테스트 보강
    
- 버그 분석
    

깊은 분석을 진행하는 역할

### 최종 세팅 철학

이 구조에서 가장 중요한 기준은 다음과 같습니다.

- JetBrains는 “항상 켜져 있는 자동완성”
    
- Gemini는 “필요할 때 호출하는 생성 도구”
    
- Codex는 “구조 작업 및 코드 퀄리티 체크 전용”

### 실제 활용 방법

#### 1. 기본 코딩

```java
userRepository.findById(userId)
```

이 단계에서는 JetBrains 자동완성을 사용합니다.  
빠르고 정확하게 이어지는 것이 중요합니다.

#### 2. 로직 생성

```java
// 사용자 상태 inactive 처리 + 로그 기록
```

이런 주석을 작성한 후 Gemini를 호출하여 코드 생성합니다.  
이 단계에서는 “속도”보다 “정확한 의도 반영”이 중요합니다.

#### 3. 테스트 코드 작성

Gemini를 사용하되, 다음과 같은 지침을 함께 제공합니다.

- fixture 기반
    
- given/when/then 구조 유지
    
- assertThatThrownBy 사용
    

이렇게 하면 기존 스타일을 유지하면서 생산성을 높일 수 있습니다.

#### 4. 구조 변경

여러 파일이 얽힌 작업은 Codex CLI로 처리합니다.

- 서비스 + 레포지토리 + 엔티티 수정
    
- 테스트 코드 동기화
    
- 리팩토링
    

이 단계는 IDE 기반 AI보다 CLI 기반 AI가 훨씬 효율적입니다.

### 예상 활용 시나리오

이 구조는 다음과 같은 상황에서 강점을 발휘합니다.

#### 1. 빠르게 CRUD 구현할 때

- JetBrains로 빠르게 코드 작성
    
- Gemini로 부족한 로직 보완

#### 2. 복잡한 서비스 로직 작성

- Gemini로 초안 생성
    
- 필요 시 여러 번 리팩토링 요청

#### 3. 테스트 코드 작성

- Gemini로 구조 생성
    
- 스타일 지침으로 품질 유지

#### 4. 리팩토링 및 구조 개선

- Codex CLI로 전체 구조 수정
    
- 테스트까지 포함한 일괄 작업

### 이 구조의 장점

이 방식으로 전환하면서 얻은 변화는 명확합니다.

- 자동완성 속도 문제 해결
    
- 코드 생성 품질 확보
    
- 테스트 스타일 유지 가능
    
- 구조 작업까지 커버 가능
    

무엇보다 중요한 것은,

> AI를 하나의 도구가 아니라 “역할을 가진 구성 요소”로 사용하게 되었다는 점입니다.

## ✏️ 메모

### Windsurf를 사용하면서 느낀 점

다음과 같은 불편함이 있었습니다.

- Gemini 보다 코드 퀄리티가 현저히 떨어집니다.
- Gemini의 다른 인사이트 참고용으로 둘 이유가 없습니다.
- “항상 쓰는 도구”라기보다 “정말 가끔 쓰는 도구”에 가까움

따라서, Windsurf는 사용하지 않기로 결정했습니다.
