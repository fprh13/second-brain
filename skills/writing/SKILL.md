# Writing Skill

## 목적
이 스킬은 Vault 전체에서 일관된 노트 작성 스타일을 유지하기 위한 기준이다. 기본 원칙은 `짧게`, `명확하게`, `연결 가능하게`이다.

## 노트 위치 규칙
- `00 Inbox`: 빠른 캡처, 미분류 메모
- `01 Permanent`: 장기 지식 노트
- `02 MOCs`: 주제 허브/목차
- `10 Projects`: 기간성 작업. 각 프로젝트는 `10 Projects/<프로젝트명>/` 폴더 아래에서 관리한다.
- `11 Areas`: 지속 관리 영역
- `12 Resources`: 참고 자료/정리
- `13 Archive`: 종료된 프로젝트/노트

## 파일명 규칙
- 형식: `핵심주제 중심 명사형`
- 불필요한 접두어/특수문자 최소화
- 잦은 리네임 금지
- 예시: `API 인증 전략`, `캐시 무효화 패턴`

## Frontmatter 규칙
- 템플릿의 frontmatter 키를 유지하고 임의 키 추가를 최소화한다.
- 공통 권장 키: `type`, `created`, `tags`, `status`
- MOC 검토 추적이 필요하면 `moc_candidate`, `moc_decision`, `needs_moc_review`를 사용한다.
- 날짜/시간 포맷: `YYYY-MM-DD`, `HH:mm`

## 헤딩/본문 스타일
- 헤딩 계층은 `# -> ## -> ###`까지만 권장
- 한 섹션은 3~6줄 내 요약 중심으로 작성
- 긴 문단보다 불릿 우선
- 체크박스는 실행 가능한 항목에만 사용
- 템플릿은 강제 폼이 아니라 느슨한 시작점으로 사용한다.
- 처음 작성할 때는 섹션을 모두 채우려 하지 말고, 본문 내용을 먼저 남긴다.

## 링크/연결 규칙
- 내부 링크는 위키링크 `[[노트명]]` 사용
- 구조 링크는 현재 폴더 체계를 따른다.
- Permanent 노트는 최소 2개 이상 관련 노트와 연결
- MOC는 단순 링크 목록이 아니라 탐색 순서를 제공

## 태그 규칙
- 태그는 최소 집합만 사용
- 중복 의미 태그 금지
- 상태 태그보다 frontmatter `status` 우선

## 코드/예시 블록
- 코드, 설정, 명령은 fenced code block으로 작성
- 언어 지정 가능하면 명시
- 긴 로그는 요약 후 핵심 라인만 남긴다

## 첨부파일 규칙
- 첨부는 `attachments/` 하위에 저장
- 노트 본문에는 파일 경로를 직접 쓰기보다 링크로 참조

## 작성 흐름 표준
1. `00 Inbox`에 캡처
2. 노트 성격에 따라 분류
3. 관련 노트 연결
4. `02 MOCs`에 반영
5. 완료된 항목은 `13 Archive`로 이동

## 품질 점검 체크리스트
- 제목이 노트 내용을 정확히 설명하는가
- Frontmatter 필수 키가 채워졌는가
- 최소 1개 이상의 내부 링크가 있는가
- MOC 또는 관련 허브와 연결되었는가
- 첨부 링크가 올바른 경로를 가리키는가
- 중복 노트 생성 가능성이 없는가

## 변경 관리 규칙
- 구조, 템플릿, 가이드 변경 시 `README.md`, `AGENTS.md`, `AGENT_KOR.md`와 정합성을 유지한다.
- 가이드 문서 갱신 시 예시 경로가 실제 Vault 구조와 일치하는지 확인한다.

## 프로젝트 노트 규칙
- Project 대표 노트는 `10 Projects/<프로젝트명>/<프로젝트명>.md` 형식을 기본으로 한다.
- 프로젝트 하위 작업 메모, 회고, ADR도 가능하면 같은 프로젝트 폴더 아래에 둔다.

## 입력 예시
```md
# spring transaction stuff

트랜잭션 고립수준이 헷갈림. read committed랑 repeatable read 차이를 다시 봐야 함.
프로젝트에서 gap lock 때문에 이상한 현상 있었음.
```

## 출력 예시
```md
---
type: permanent
created: 2026-03-11
tags: [permanent]
status: evergreen
---

# 트랜잭션 격리 수준

## 핵심 주장
- 격리 수준 선택은 데이터 일관성과 동시성 비용의 균형 문제다.

## 관련 이슈
- gap lock은 구현체에 따라 팬텀 리드 방지 전략과 연결된다.
```

## 템플릿 연결
- Inbox 초안은 목적에 맞는 템플릿으로 승격한다.
- 템플릿 키가 이미 있으면 유지하고, 비어 있는 값만 우선 채운다.
- 템플릿 섹션이 맞지 않으면 합치거나 비워둬도 된다.
- `moc_decision`은 `pending`, `linked`, `skipped` 중 하나로 남기고, 새 MOC 자동 생성은 하지 않는다.
