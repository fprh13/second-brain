# OMX 지양

## 개요
OMX를 지향하기로 했던 나의 생각을 정리한 문서입니다.

## 메모
### 1. OMX를 처음 선택한 이유
AI를 단순한 코드 자동완성 도구가 아니라, 개발 흐름 안에서 반복적으로 동작하는 시스템으로 활용하고 싶었습니다.
그 과정에서 “멀티 에이전트 실행”과 “자동 반복 루프”를 빠르게 실험할 수 있는 도구가 필요했고, 그 요구에 가장 잘 맞았던 것이 OMX였습니다.

OMX는 `$team`, `$ralph`, `autopilot` 같은 실행 모드를 통해
- 병렬 작업 실행
- 반복 루프 처리
- 작업 흐름 자동화

를 별도의 설계 없이 바로 사용할 수 있게 해줍니다.

즉, AI를 단발성 호출이 아니라 **하나의 실행 시스템처럼 다뤄볼 수 있는 환경**이라는 점에서 선택했습니다.

### 2. OMX를 사용하면서 얻은 것
OMX를 통해 가장 크게 얻은 것은 다음 세 가지입니다.

첫째, AI를 “도구”가 아니라 **실행 단위(Agent)**로 바라보게 되었습니다.
코드를 생성하는 역할, 테스트를 수행하는 역할, 검증하는 역할을 나눌 수 있다는 것을 경험했습니다.

둘째, 반복 실행 구조의 중요성을 이해하게 되었습니다.
`generate → test → fix → repeat` 같은 흐름이 자동화될 때, AI의 활용 방식이 완전히 달라진다는 것을 느꼈습니다.

셋째, 병렬 실행의 효과를 체감했습니다.
여러 작업을 동시에 진행할 수 있다는 점은 단순 생산성 향상을 넘어서, 작업 방식 자체를 바꿉니다.

### 3. OMX의 한계라고 느낀 부분
OMX는 강력하지만, 동시에 명확한 한계도 존재합니다.

가장 크게 느낀 점은 **“이미 정의된 실행 프레임워크”라는 점**입니다.

OMX는 다음과 같은 특징을 가집니다:

- `$team`, `$ralph` 같은 **모드 중심 구조**
- 권장 실행 흐름이 존재
- 내부적으로 이미 설계된 orchestration + harness 구조

이로 인해 느낀 한계는 다음과 같습니다:

- 워크플로우를 내가 정의하기보다는 **정해진 흐름을 사용하게 된다**
- 루프 구조나 실패 처리 방식 등을 **세밀하게 제어하기 어렵다**
- 프로젝트별로 다른 실행 구조를 만들기에는 제약이 있다

즉, 빠르게 시작하기에는 좋지만
**“내 시스템을 설계하는 단계”에서는 부족함을 느꼈습니다**

### 4. 생각의 전환
OMX를 사용하면서 자연스럽게 다음과 같은 질문이 생겼습니다.

> “이 구조를 내가 직접 만들 수는 없을까?”

특히 `$ralph`를 사용하면서 깨달은 점은,
이것이 특정 툴의 기능이 아니라 **반복 실행 패턴**이라는 점이었습니다.

즉,

- Ralph = 기능 ❌
- Ralph = 패턴 ⭕

이걸 인지하면서 방향이 바뀌었습니다.

### 5. 이후 지향하게 된 방향
OMX를 계속 사용하는 대신, 다음과 같은 구조를 지향하게 되었습니다.

- 사용자 정의 에이전트 구성
- 작업을 스킬 단위로 분리 (구현, 테스트, 수정 등)
- 워크플로우를 문서와 규칙으로 정의
- 반복 실행과 실패 처리를 포함한 하네스 설계
- 필요 시 CMUX를 활용한 병렬 실행 환경 구성

이 구조는 OMX처럼 완성된 프레임워크를 사용하는 것이 아니라,

👉 **내가 직접 실행 구조를 설계하는 방식**

입니다.

### 6. OMX vs 내가 지향하는 방식
OMX는 다음과 같이 정리할 수 있습니다:

- 완성된 orchestration + harness 제공
- 빠른 실험 가능
- 낮은 초기 비용
- 제한된 제어권

반면 내가 지향하는 방식은 다음과 같습니다:

- 워크플로우 직접 정의
- 하네스 직접 설계
- 높은 자유도
- 높은 초기 비용

### 7. 결론
OMX는 AI 기반 개발을 처음 이해하는 데 매우 좋은 도구였습니다.
특히 멀티 에이전트 실행과 반복 루프 구조를 빠르게 경험할 수 있다는 점에서 큰 도움이 되었습니다.

하지만 궁극적으로는
“이미 만들어진 시스템을 사용하는 것”보다
“내 프로젝트에 맞는 실행 구조를 직접 설계하는 것”이 더 중요하다고 판단했습니다.

그래서 현재는 AI 실행 구조(Harness + Orchestration)를 직접 설계하는 방향을 지향하고 있습니다.
