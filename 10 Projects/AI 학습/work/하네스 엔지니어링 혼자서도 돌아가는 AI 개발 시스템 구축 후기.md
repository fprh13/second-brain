# 하네스 엔지니어링 혼자서도 돌아가는 AI 개발 시스템 후기

---

## 📄 개요
인프런 챌린지 하네스 엔지니어링: 혼자서도 돌아가는 AI 개발 시스템 구축을 진행한 후기입니다.

---

## ✏️ 메모

### 왜 신청하게 되었는가
Codex를 사용하면서 oh-my-codex를 적극적으로 활용했습니다. 그런데, oh-my-codex를 지양하자는 쓰레드의 글들이 많이 보였습니다. 플러그인 없이 자신의 팀 상황에 맞는 **하네스**를 구축해야 한다는 주장이 많았죠.
당시 저에게 하네스라는 것은 추상적으로 느껴져서 크게 와닿지 않았습니다. 올해 AI의 키워드가 **하네스 엔지니어링**이라고 하는데, 인프런 챌린지를 통해서 **하네스**와 친해지고자 했습니다.

### 챌린지 준비
하네스 엔지니어링에 대해서 이해한 뒤, 해당 챌린지를 진행하는 것이 좋다고 생각했습니다. 챌린지 시간이 2시간으로 굉장히 짧기 때문이기도 했고, 강사님께서 실무에서 어떻게 적용하고 있는지를 보여주는 취지가 강해 보였기 때문이었습니다. 강사님의 의도를 확실히 이해하기 위해 하네스 엔지니어링에 대해 학습하고 직접 구축해보며 준비했습니다.

### 어떻게 학습했는가?
하네스 관련 영상을 굉장히 많이 시청했습니다. 개인 프로젝트에 **하네스**를 구축해보는 실습도 진행했습니다.
저만의 하네스 구성은 다음과 같습니다. (SDD로 진행)
- pre-commit을 Codex Hooks에 적용
- sub-agent 구성
  - coder
  - tester
  - fixer
  - reviewer
- 오케스트레이션 Skill 작성 (리더 sub-agent보다 Skill로 진행했음)
  1. coder → implement feature
  2. tester → generate tests
  3. run verify script
  4. if failed → fixer → retry
  5. if success → reviewer

즉, AI에게 "개발하거나 커밋할 때 테스트 해줘"하고 부탁하던 과정을 강제하도록 만들었습니다.
사용자의 개입 없이 테스트가 강제되어, 문제점이 발견되면 스스로 개선하도록 강제되었습니다.

### 챌린지 후기
사전에 미리 **하네스**에 대해 학습하고 실습해보고 듣길 잘한 것 같습니다.

강사님께서는 SDD를 개선하기 위해 티켓 주도 개발로 개선했다고 하셨습니다. ChatGPT + Cursor로 진행하셨고, ChatGPT에 `Template.md`를 프롬프트에 업로드하여 티켓을 생성한 뒤, Cursor로 해당 티켓 업무를 처리하는 방식이었습니다.

놀랐던 점은 참고해야 할 md 파일의 길이가 굉장히 길고 많았다는 것입니다. 이 수많은 컨텍스트를 AI가 항상 지킬까?에 대한 의문이 들었고, 동시에 md 파일들의 유지보수성이 중요하다는 걸 느꼈습니다.

저는 강사님이 소개해주신 방식이 컨텍스트 엔지니어링에 가깝다고 느꼈습니다. 컨텍스트를 잡아주고 질의응답 후 중간중간 사람의 개입으로 진행된다는 점에서 컨텍스트 엔지니어링에 가깝다고 느끼게 되었습니다.

물론, 강사님께서도 제어권이 개발자에게 있는 커스텀 하네스라고 하셨습니다. **하네스**라는 용어가 넓게 쓰이기에 시선의 차이라고 생각합니다.

취업 준비 중인 신입 개발자 입장에서 굉장히 좋은 인사이트가 되었습니다. SDD와 많이 언급되는 티켓 주도 개발을 직접 확인하고 싶었는데, 너무 좋은 시간이었습니다.
