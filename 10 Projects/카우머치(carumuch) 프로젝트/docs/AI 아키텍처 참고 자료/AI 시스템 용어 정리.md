## 2. 가장 먼저 알아야 하는 큰 개념

### AI

사람이 직접 규칙을 하나하나 다 적지 않아도, 데이터에서 패턴을 배워서 결과를 내는 프로그램을 말한다.

이 프로젝트에서는 완전히 하나의 AI가 다 하는 게 아니라, 여러 기술이 섞여 있다.

- 이미지 특징을 뽑는 AI
- 손상 위치를 찾는 AI
- 과거 견적 데이터를 읽는 일반 코드

즉 `AI + 일반 프로그램 로직`이 섞인 구조다.

### 모델

AI가 실제로 계산할 때 사용하는 핵심 프로그램 덩어리라고 보면 된다.

쉽게 말하면:

- 사람은 문제를 보고 판단한다.
- 모델은 숫자로 바뀐 데이터를 보고 판단한다.

이 프로젝트에서는 대표적으로 두 종류 모델이 나온다.

- `VGG16`
- `U-Net`

### 학습

AI 모델을 만드는 과정이다.

쉽게 말하면:

1. 사고 사진과 정답 데이터를 많이 모은다.
2. 모델이 처음에는 틀리게 예측한다.
3. 틀릴 때마다 내부 숫자를 조금씩 바꾼다.
4. 이 과정을 아주 많이 반복한다.
5. 어느 정도 맞추게 되면 그 결과를 파일로 저장한다.

즉 `학습`은 모델을 훈련시키는 과정이다.

중요한 점:

- 학습은 모델을 `만드는 단계`
- 추론은 만들어진 모델을 `사용하는 단계`

현재 저장소에는 학습 코드보다 `이미 학습된 모델을 불러와 사용하는 코드`가 중심이다.

### 추론

이미 만들어진 AI 모델을 실제 입력에 적용해서 결과를 얻는 과정이다.

예를 들면:

- 사진 1장을 넣는다.
- 모델이 손상 위치를 찾는다.
- 과거 사례 중 비슷한 사진을 찾는다.

이게 바로 추론이다.

현재 `app.py`는 대부분 추론 코드다.

### 데이터셋

AI가 학습하거나 평가할 때 쓰는 데이터 모음이다.

예를 들어:

- 사고 차량 사진
- 사진마다 붙은 손상 부위 정답
- 실제 수리 부품 목록
- 실제 견적 금액

이런 것들이 모이면 데이터셋이 된다.

현재 저장소에는 일부 결과 파일은 보이지만, 학습에 쓴 전체 데이터셋은 보이지 않는다.

## 4. 이미지 AI 관련 핵심 용어

### VGG16

이미지를 분석할 때 쓰는 유명한 딥러닝 모델 이름이다.

쉽게 말하면:

- 사진을 숫자 특징으로 바꾸는 데 강한 오래된 대표 모델

이 프로젝트에서는 `이 사진이 무엇인지 분류`하려고 직접 쓰는 게 아니라, `이 사진이 다른 사진과 얼마나 비슷한지` 보기 위한 특징 추출기로 사용한다.

### U-Net

이미지에서 픽셀 단위로 영역을 나누는 데 많이 쓰는 모델 구조다.

쉽게 말하면:

- 사진 안에서 "어디가 손상인지" 칠해주는 모델

이 프로젝트에서는 손상 유형별로 U-Net 모델을 여러 개 사용한다.

### CNN

이미지 처리에 많이 쓰이는 딥러닝 구조 종류다.  
`Convolutional Neural Network`의 줄임말이다.

VGG16과 U-Net은 모두 이미지 처리 계열 모델이고, 이런 계열을 넓게 보면 CNN 기반이라고 생각하면 된다.

### Segmentation

이미지 안에서 픽셀 단위로 무엇이 어디에 있는지 나누는 작업이다.

쉽게 말하면:

- 사진 전체를 그냥 한 번에 보는 게 아니라
- 픽셀마다 "손상", "배경"처럼 구분하는 것

이 프로젝트의 `/segment`가 이 역할을 한다.

### Mask

세그멘테이션 결과로 만들어지는 표시 지도다.

쉽게 말하면:

- 손상 위치만 하얗게 칠한 흑백 지도
- 또는 손상 영역만 1로 표시한 배열

모델은 보통 mask를 만들고, 그걸 색으로 덧칠해서 사람이 보기 쉽게 바꾼다.

### Overlay

원본 이미지 위에 결과를 겹쳐서 보여주는 방식이다.

이 프로젝트에서는 손상 위치를 색깔로 칠한 후, 원본 사진 위에 반투명하게 덧씌운다.

### Alpha Blending

이미지 두 장을 반투명하게 섞는 방식이다.

쉽게 말하면:

- 원본 사진 70%
- 색칠한 손상 결과 30%

이렇게 섞어서 보기 좋게 만드는 것이다.

## 5. 유사사고 검색 관련 용어

### Feature Vector

이미지를 숫자 묶음으로 바꾼 결과다.

쉽게 말하면:

- 사람은 사진을 눈으로 본다.
- 컴퓨터는 사진을 숫자 특징 묶음으로 본다.

그 숫자 묶음이 feature vector다.

### Embedding

feature vector와 거의 비슷하게 쓰이는 말이다.

쉽게 말하면:

- 어떤 대상을 비교하기 좋게 숫자로 압축한 표현

이 프로젝트에서는 사고 사진을 embedding으로 바꾼 뒤, 다른 사고 사진들과 비교한다.

### `fc1`

VGG16 안쪽에 있는 레이어 이름 중 하나다.

이 프로젝트에서는 최종 정답 클래스를 쓰는 게 아니라, 이 `fc1`에서 나온 숫자 벡터를 가져다 유사도 비교에 쓴다.

쉽게 말하면:

- VGG16이 사진을 보고 만든 중간 특징 요약본

### Cosine Similarity

두 숫자 벡터가 얼마나 비슷한지 재는 방법이다.

쉽게 말하면:

- 두 사진이 비슷한 방향의 특징을 가지는지 보는 점수

이 프로젝트에서는 입력 사진과 과거 사고 사진들을 비교할 때 이 값을 쓴다.

값이 높을수록 더 비슷하다고 본다.

### Cosine Distance

코사인 유사도와 비슷한 말인데, 보통 "멀다/가깝다" 관점에서 표현할 때 쓴다.

코드에서는 `1 - cosine(...)` 형태로 계산해서 비슷한 정도를 만든다.

### Similarity Score

얼마나 비슷한지 숫자로 표현한 값이다.

이 프로젝트에서는 이 점수가 가장 높은 과거 사고 사례를 선택한다.

### Nearest Neighbor

가장 가까운 데이터를 찾는 방식이다.

쉽게 말하면:

- 입력 사진과 가장 닮은 과거 사진 1장을 찾는 것

이 프로젝트의 유사사고 검색이 거의 이 방식이다.

### Top-1

가장 점수가 높은 1개만 선택하는 방식이다.

현재 시스템은 대부분 `Top-1` 방식이라, 잘못된 사례 하나가 전체 결과를 틀리게 만들 수 있다.

### Top-k

가장 비슷한 결과를 여러 개 뽑는 방식이다.

예를 들어:

- Top-3
- Top-5

이런 식으로 여러 후보를 보고 더 안정적으로 판단할 수 있다.

## 6. 견적과 비용 계산 관련 용어

### 견적 JSON

견적 정보를 저장해 둔 파일 형식이다.

JSON은 사람이 읽기 쉬운 데이터 저장 형식이다.  
예를 들어 아래 같은 구조다.

- 수리내역
- 부품가격
- 공임

이 프로젝트는 유사사고를 찾은 뒤, 그 사고와 연결된 JSON에서 비용을 읽는다.

### 공임

사람이 수리 작업을 하면서 드는 인건비 성격의 비용이다.

쉽게 말하면:

- 부품값 말고 작업비

### 부품가격

실제로 교체하거나 사용하는 부품 자체의 가격이다.

### 총금액

여러 수리 항목의 `부품가격 + 공임`을 전부 더한 금액이다.

현재 시스템은 AI가 직접 총금액을 계산해내는 게 아니라, 유사한 과거 사례의 견적 데이터를 합산한다.

### Rule-based

AI가 아니라 사람이 정한 규칙대로 처리하는 방식이다.

예를 들어:

- 값이 비어 있으면 0으로 처리
- 부품가격과 공임을 더한다

이런 것은 rule-based 처리다.

현재 프로젝트는 견적 계산 부분에 이런 규칙 기반 코드가 들어 있다.

## 8. 이미지 처리 관련 용어

### OpenCV

이미지와 영상을 다룰 때 자주 쓰는 라이브러리다.

이 프로젝트에서는 이미지 읽기, 색상 변환, 크기 조정 등에 사용된다.

### PIL / Pillow

파이썬에서 이미지를 쉽게 열고 저장하는 도구다.

이 프로젝트에서는 이미지 열기, 크기 조정, PNG 저장 등에 사용된다.

### Resize

이미지 크기를 바꾸는 것이다.

예를 들어:

- `224 x 224`
- `256 x 256`

모델마다 원하는 입력 크기가 달라서 resize를 한다.

### RGB / BGR

이미지 색상 채널 순서를 말한다.

- RGB: 빨강, 초록, 파랑 순서
- BGR: 파랑, 초록, 빨강 순서

OpenCV는 보통 BGR을 쓰기 때문에, 다른 라이브러리와 맞추려고 RGB로 바꿔주는 코드가 자주 나온다.

### Normalization

숫자 크기를 일정한 범위로 맞추는 과정이다.

예를 들어 픽셀값 0~255를 0~1로 바꾸는 것이 대표적이다.

모델이 계산하기 쉽게 만들기 위해 한다.

### Tensor

AI 모델이 계산할 때 쓰는 숫자 덩어리다.

쉽게 말하면:

- 일반 배열보다 AI 계산에 더 최적화된 숫자 상자

PyTorch나 TensorFlow는 보통 tensor를 입력으로 받는다.

## 9. 평가와 성능 관련 용어

### 정확도

모델이 얼마나 자주 맞추는지를 나타내는 대표 표현이다.  
하지만 상황에 따라 의미가 달라질 수 있다.

예를 들면:

- 부품을 맞췄는지
- 손상 위치를 맞췄는지
- 금액이 실제와 가까운지

이건 서로 다른 정확도다.

그래서 그냥 "정확도 몇 %"라고만 하면 부족할 때가 많다.

### MAE

평균 절대 오차다.

쉽게 말하면:

- 예측 금액과 실제 금액이 평균적으로 얼마나 차이 나는지

금액 평가에 자주 쓴다.

### MAPE

평균 절대 백분율 오차다.

쉽게 말하면:

- 실제 값 대비 몇 % 정도 틀렸는지를 평균낸 것

견적 시스템에서는 이 지표가 특히 유용하다.

### Precision / Recall / F1

분류나 검출 결과를 평가할 때 자주 쓰는 지표다.

초보자용 간단 해석:

- Precision: 맞다고 한 것 중 진짜 맞은 비율
- Recall: 진짜 맞아야 하는 것 중 찾아낸 비율
- F1: Precision과 Recall의 균형 점수

부품 예측 성능을 볼 때 유용하다.

### IoU

세그멘테이션이나 검출에서 많이 쓰는 지표다.

쉽게 말하면:

- 예측한 영역과 실제 정답 영역이 얼마나 겹치는지

손상 위치를 얼마나 잘 맞췄는지 볼 때 쓴다.

### Dice

IoU와 비슷하게 세그멘테이션 품질을 재는 지표다.

역시 손상 영역을 얼마나 잘 맞췄는지 볼 때 자주 쓴다.

### Confidence

결과에 대한 시스템의 자신감 정도다.

쉽게 말하면:

- "이 결과를 얼마나 믿을 만한가?"

현재 시스템은 이 confidence를 사용자에게 충분히 보여주지 않는다.

## 10. 개발과 구조 관련 용어

### Refactoring

겉으로 보이는 기능은 크게 안 바꾸면서, 내부 코드를 더 읽기 쉽고 유지보수하기 좋게 정리하는 작업이다.

예를 들면:

- 긴 파일을 나눈다
- 중복 코드를 줄인다
- 함수 역할을 분리한다

### Legacy

오래되었거나, 현재 기준으로 구조가 낡은 방식의 코드를 말한다.

꼭 틀렸다는 뜻은 아니고, 보통:

- 구조가 섞여 있고
- 테스트가 부족하고
- 확장성이 낮은 상태

를 의미할 때가 많다.

### MLOps

AI 모델을 실제 서비스에 안정적으로 올리고 관리하는 운영 방식이다.

예를 들어:

- 모델 버전 관리
- 성능 측정
- 배포 관리
- 모니터링

이런 것들을 포함한다.

### Observability

시스템이 지금 잘 돌아가는지, 어디서 실패하는지 보이게 만드는 능력이다.

예를 들어:

- 에러 로그
- 응답 속도
- 실패율
- 낮은 신뢰도 비율

이런 것들을 볼 수 있어야 한다.

## 11. 이 프로젝트를 이해할 때 가장 중요한 한 줄 요약

이 프로젝트는 `사고 이미지를 직접 보고 견적을 완전히 새로 계산하는 AI`라기보다, `이미지를 숫자 특징으로 바꿔 과거 유사사고를 찾고, 그 사례의 견적 정보를 가져오며, 동시에 손상 위치를 색으로 보여주는 시스템`이라고 이해하는 것이 가장 정확하다.

## 12. 아주 짧은 핵심 요약

- `학습`: AI를 만드는 과정
- `추론`: 만들어진 AI를 쓰는 과정
- `VGG16`: 유사사고 찾기 위한 특징 추출기
- `U-Net`: 손상 위치 찾는 모델
- `코사인 유사도`: 사진끼리 얼마나 비슷한지 재는 점수
- `.pt`: 학습된 모델 파일
- `.pkl`: 저장된 특징 데이터 파일
- `공임`: 작업비
- `견적 JSON`: 과거 수리 내역과 비용 데이터 파일
