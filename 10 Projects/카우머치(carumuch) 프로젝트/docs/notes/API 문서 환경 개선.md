# API 문서 환경 개선

---

## 📄 본문
### API 문서 개선
프론트엔트 팀원이 피드백을 주었다. 
1. 시나리오 별 예제가 부족해 API를 연동하는데 어려움이 있었다.
2. API 문서인 만큼 서버 실행 유무와 상관없이 언제든 확인했으면 좋겠다.
3. 문서가 언제 최신화 되었는지 몰라서 변경 사항이 생겼는지 파악하기 어렵다
라는 피드백을 받게 되었다.

이를 해결하기 위해, 테스트 기반으로 시나이로별 200, 400, 500 등 시나리오에 맞게 API 스니펫들이 Open API 파일로 산출되도록 RestDocs와 OAS3를 결합한 환경을 구현했다.

테스투 후에 스니펫이 생기고 최종 OAS 파일이 생기기에, CI 과정에서 API 문서 레포지토리에 테스트 산출물을 반영하도록 구성했다. 해당 API 문서는 Swagger에서 제공하는 Swagger-UI로 구성 되어있고, 새로운 반영에 트리거가 되어서, vercel에 배포되는 구조이다.

테스트 기반이라 오차 없는 확실한 API 문서가 되었고, 시나리오 별 API 예제가 풍부해졌으며 서버 실행 상관없이 문서를 확인할 수 있게 되었다. 또한 산출 시간을 OAS 파일에 포함 시켜 최신화 날짜를 확인할 수 있게 되어 프론트엔드 개발자의 피드백을 모두 수용하게 되었다.

최종적으로, 프론트엔드 개발자가 늘 최신화된 신뢰기반의 AP문서를 확인 할 수 있게 되었다.

#### point
##### RestDocs + OAS3 환경 사용 후기
RestDocs 기반이기 떄문에 비즈니스 코드에 문서화와 관련된 코드를 추가할 필요가 없다는 점이 좋았다. 그리고 Test 코드 통과가 필수 조건으로 충족되어야 문서가 생성이되기 때문에 유지보수성이 좋고, 실수에 대한 불안감이 줄어든다는 점이 좋았다.

기존 아스키독스를 사용할 때보다 더 좋은 디자인과 가독성을 제공하는 Swagger UI를 제공하면서, API 테스트 기를 사용할 수 있다는 점이 좋았다. 또한 정적 파일이기 때문에 따로 문서 서버를 만들수 있고, 여러 API 문서가 있는 MSA 환경에서 하나의 문서 서버에 통합해서 확인 할 수 도 있어 정말 만족스러운 조합이였다.

##### Vercel 배포
API문서는 PR MERGE 시 트리거를 두어서 테스트의 산출물 데이터에 변경이 생기면 문서 레포에 반영되고, vercel이 식별해서 Swagger UI 위에 띄우는 형식이다. 따라서, 프론트엔드 개발자가 늘 최신화된 신뢰기반의 API 문서를 확인할 수 있게 되었다.
