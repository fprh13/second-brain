## 추가 기술·운영 질문

기존 백엔드 설계의 T01~T06과 연계되는 질문입니다. 해당 설계를 읽지 않아도 아래 사항은 결정해야 하며 이 패키지가 기존 결정을 승인하지 않습니다.

|연계|결정 대상|근거·후속 산출물|
|---|---|---|
|T01|Java/Spring Boot/Gradle/DB·마이그레이션·테스트 환경|현재 저장소 build 선언은 Java 17, Boot 4.2.0, Gradle 9.9.2, Spring AI 2.1.0-M1입니다. 운영 채택 검토 없이 버전을 변경하지 않습니다. 재현 가능한 테스트 계획이 필요합니다.|
|T02|원본 카탈로그/권리·외부 ID·시즌·적재|프론트 fixture는 단일 제목 12개뿐입니다. 실제 샘플·매핑·중복/실패 처리와 포스터 권리를 확보합니다.|
|T03|DB 검색 정렬/커서 서명·만료·페이지 일관성|Mock global revision 방식은 운영 결정이 아닙니다. 다른 사용자의 쓰기와 페이지 경계의 기대값을 합의합니다.|
|T04|프로필 동시 수정|현재 무버전 PATCH입니다. 최종 쓰기 우선 또는 조건부 수정 중 선택하고 프론트 충돌 UX를 정합니다.|
|T05|AI 제공자·모델·예산·출력 검증·타임아웃·개인정보|현재 프론트에는 AI 연동이 없습니다. 후보 ID 기반 검증을 제안하되 자유 제목 출력이 필요하면 언어/별칭/시즌 매칭과 모호성 거부 기준을 정합니다.|
|T06|규모·SLO·추천 SLA·rate limit·보관·관측|Mock 300ms/4초/30초 폴링 값을 서비스 보장 시간으로 쓰지 않습니다. 실제 측정과 운영 기준을 합의합니다.|

## 구현 착수와 계약 인계 게이트

1. 요구/가정/제안을 분리하여 A01/A02/A08 인증·오류 계약부터 결정합니다. 결정자·한국 시간 날짜·선택안·근거·미해결 범위를 기록합니다.
2. A03/A09/A06과 원본 데이터를 먼저 확인해 기록 enum/UNIQUE/작품 관계를 설계합니다. 미정 상태에서 운영 마이그레이션을 고정하지 않습니다.
3. A04 조건부 쓰기·멱등성과 A07 삭제/프로필, A05 추천 상태·AI 장애의 계약 예시를 작성합니다. H01~H11의 해결/허용/후속 범위를 각 항목에 연결합니다.
4. 프론트 담당자에게 API 변경 전후, 필드 nullable/optional·오류 code·헤더·상태·검색 정책·예시를 전달합니다. 승인된 별도 명세를 만들고 생성 타입·MSW·테스트·UI를 함께 갱신합니다. 원본 snapshot은 보존합니다.
5. 실제 서버 연동 시 가입→검색→완료/중단 등록→수정→삭제→프로필→로그아웃·재로그인, 타인 접근·중복·충돌·추천 실패·세션 만료를 검증합니다. Mock 전용 초기화 없이 서버 영속성과 실제 쿠키를 확인합니다.

이번 산출물은 위 결정을 준비하기 위한 분석이며 정책 승인, 운영 DB 변경, 실제 백엔드 개발 또는 출시 완료를 뜻하지 않습니다.
