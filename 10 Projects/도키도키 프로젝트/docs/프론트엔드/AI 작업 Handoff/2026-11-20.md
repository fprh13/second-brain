    - **프로필 수정(`/profile`, 829)**: 닉네임 단독 수정 폼(`ProfileEditForm`), 최초 서버 데이터를 폼 기본값으로 고정하여 백그라운드 재조회 시 입력 덮어쓰기 방지, 가입과 동일한 Zod 닉네임 규칙 재사용(trim 후 1~16자 검사), 미변경 값 감지 및 안내 후 불필요한 요청 차단, pending 중 입력 및 중복 제출 차단, 미저장 상태 이탈 시 인라인 확인 및 `beforeunload` 탭 닫기 경고 제공
    - **수정 완료(`/profile/done`, 849)**: PATCH 성공 응답으로 전달된 닉네임 및 사용자 ID state(`{kind: 'profile-updated', userId, summary: {nickname}}`) 유효성 검증(`ResultView`), 직접 URL 접근 및 타 사용자 결과 state 진입 시 `/my`로 replace 리다이렉트
    - **공통 컴포넌트 재사용 및 확장 배제**: `AppHeader`, `BottomAction`, `Button`/`ButtonLink`, `TextField`, `ResultView`, `QueryFeedback`, `LogoutButton`, `BottomNavigation`(하단 탭) 재사용. 원본에 없는 이메일 표시·수정/탈퇴/아바타 등 임의 기능 확장 배제
- **HTTP 계약 준수 및 캐시 동기화·격리**
    - 기존 API 함수(`getMe`, `updateProfile`, `getRecordSummary`, `logout`) 및 MSW handler 재사용 (OpenAPI 계약 초안 유지)
    - **캐시 동기화 및 늦은 GET 취소**: 현재 사용자 캐시는 `['me']` 하나로 관리, PATCH 응답(전체 User 객체)으로 캐시를 갱신하기 전 진행 중인 `/me` GET 요청을 취소(`cancelQueries`)하여 이전 응답이 최신 프로필을 덮어쓰는 레이스 컨디션 차단, 요청 사용자와 캐시 사용자 ID 불일치 시 미반영
    - **사용자 전환 및 세션 격리**: 집계 쿼리는 `['record-summary', userId]`로 사용자 격리, 로그인·회원가입·로그아웃 시 `replaceSession`으로 기존 사용자 쿼리 취소 및 개인 캐시 완전 제거, 프로필 mutation `gcTime: 0` 적용으로 계정 전환 시 이전 mutation 상태 누출 차단
    - **에러 매핑 및 복구**: 401(세션 만료 시 이탈 차단 해제 후 세션 정리 및 로그인 복귀), 403(권한/보안 오류 안내 및 입력 유지), 422(닉네임 필드 에러 연결), 429(Retry-After 안내 및 저장 잠금), 5xx/네트워크 오류 시 입력값 보존 및 수동 재시도 제공 (자동 재시도 없음)
    - MSW 사용자 Map 갱신을 통해 후속 GET 및 동일 세션 재로그인 시 변경된 닉네임 영속 확인
- **16개 화면 Mock 흐름 완료**
    - P0-1~3(기반·라우트·API/MSW), P1(토큰·공통 UI), P2(인증 3개), P3(탐색 4개), P4(기록 3개), P5(수정/삭제 3개), P6(마이/프로필 3개)까지 전체 16개 화면의 Mock 기반 기능 흐름 완료
