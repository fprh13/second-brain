## 자산·운영 확인

- 포스터 12개는 `out/assets/photos`와 `out/credits.json`을 유지합니다. 출처 기록만으로 상용 이용 허가가 확인된 것은 아닙니다. 권리·원본 제공처·배포 CDN·이미지 대체 정책을 콘텐츠 담당자가 확인합니다. 디자인 분석 중 외부 이미지를 새로 수집하지 않았습니다.
- Pretendard v1.3.9 가변 WOFF2 한 개와 SIL OFL 1.1을 앱에 포함해 자체 호스팅합니다. 로딩 실패 fallback은 Chromium에서 검증했으며 실제 화면 줄바꿈 비교는 후속 UI 단계에 남아 있습니다.
- 배포 호스트·API 프록시·CSP·브라우저 지원 범위는 P0/P8에서 확정합니다. 신규 공개 SEO 페이지 요구가 생길 경우에만 SSR 선택을 재검토합니다.

- A01~A08은 미합의 상태를 유지합니다. 기존 쿠키/CSRF 초안은 draftSession과 앱 client 어댑터에 격리하며 자동 토큰 갱신은 추가하지 않습니다.

- mock 세션은 메모리이며 비밀번호를 저장하지 않습니다. 실제 쿠키 보안/재로그인 정책 검증을 대체하지 않습니다. 자세한 제한은 [API 사용 안내](09-api-foundation.md)를 확인합니다.

## P3 검색·P4 기록 결정 기록 (2026-11-20)

- **A09: 시청 상태 확장 협의 필요** — 이번 요청에는 완료 사유와 나중에 보기가 있지만 FigCraft 641/1065와 OpenAPI WatchEntry는 완료 평가 또는 중단 사유만 허용합니다. 사용자 지침의 기존 계약 우선 원칙에 따라 완료 평가 1~5, 중단 사유 1~200만 구현했습니다. 완료 사유 필수 여부·길이, 나중에 보기의 enum·이력 필터·집계·추천 영향은 제품/백엔드 합의 전입니다. 임의 필드나 상태를 API에 추가하지 않았습니다.
- A03/A04/A06은 기존 초안 그대로입니다. 작품당 1개, 중복 409 기존 수정 링크, 동일 body 재시도에 동일 멱등키를 사용합니다. 저장 실패 후 body가 달라지면 새 키를 발급합니다.
- 검색 초기 목록은 API title,id 정렬을 유지합니다. FigCraft의 예시 배열 순서를 강제하지 않습니다. 목록은 Query infinite 캐시에 누적하며 다음 커서는 서버 응답에서만 받습니다. q/status 변경 시 첫 페이지로 돌아갑니다.
- 이력 새로고침·오류 재시도·빈 상태·미저장 이동 안내는 최소 복구 UI입니다. 미저장 안내는 인라인 alert와 계속 작성/나가기 버튼으로 제공하며 modal dialog를 만들지 않았습니다. 저장 중 내부 이동은 차단합니다.
- MSW는 기존 메모리 DB를 재사용합니다. 새로고침 시 mock 데이터/세션 초기화 제한은 유지합니다. 실제 서버의 영속성·소유권 검증을 대신하지 않습니다.


## P5 수정·삭제 결정 기록 (2026-11-20)

- A03/A04/A09는 미합의 상태입니다. 기존 `WatchEntry`의 완료↔중단 전환만 제공하고 PUT은 활성 entry 전체를 교체합니다. 이전 상태 필드는 서버 저장본에서 제거하며, 화면 전환 중 로컬 입력 보존은 저장 정책과 구분합니다. 완료 사유·나중에 보기 enum/필터/집계/추천 영향은 확정하지 않았습니다.
- GET/PUT/DELETE `/records/{recordId}`, 수정 200·삭제 204, `If-Match` 필수와 412/428, 타인 기록 404는 기존 초안을 재사용했습니다. 실제 서버의 소프트/하드 삭제·보관 기간·복구 가능 여부는 미정이며 UI는 복구 기능을 약속하지 않습니다.
- D06 삭제 확인은 native modal dialog로 보완했습니다. 취소/Escape와 포커스 복원, 처리 중 취소/중복 실행 차단을 제공합니다. 원본에는 확인창이 없으므로 최종 디자인 승인으로 간주하지 않습니다.
- 편집 시작 값과 version은 고정하고 백그라운드 조회로 덮지 않습니다. 충돌 시 입력을 유지한 뒤 사용자가 명시적으로 최신 조회·초기화를 선택합니다. 쓰기 자동 재시도나 강제 덮어쓰기는 하지 않습니다. 통신 실패로 성공 여부가 불확실한 재시도는 기존 버전 검증에 따라 충돌/미존재 안내로 이어질 수 있습니다.
- 삭제 성공 후 목록 캐시에서 행을 제거하고 상세를 폐기합니다. 이력·집계·작품·추천을 재검증하며 추천 조회 실패를 삭제 실패로 되돌리지 않습니다. 삭제 결과는 보관한 작품 제목을 사용하고 삭제 리소스를 재조회하지 않습니다.
- Mock 새로고침은 DB/세션을 초기화하므로 삭제 재접근 검증은 같은 브라우저 세션의 SPA 이동과 HTTP 테스트로 수행합니다. 실제 서버의 영속성·동시 수정·소유권·쿠키는 P8에서 확인해야 합니다.


## P6 마이·프로필 결정 기록 (2026-11-20)

- A02/A07: 원본과 기존 ProfileInput의 nickname만 수정합니다. trim 후 1~16자는 초안이며 중복 허용, Unicode 길이 계산, 변경 주기/횟수 제한은 미정입니다. 이메일 표시/편집·탈퇴를 추가하지 않았으며 이메일 변경의 본인 확인·재인증·세션 회전 정책은 별도 합의가 필요합니다.
- 프로필 PATCH에는 version/If-Match가 없습니다. 동시 수정 충돌 정책은 백엔드와 협의해야 하며 현재 폼은 편집 시작 값을 유지합니다. 미변경 값은 HTTP 요청 없이 안내합니다.
- 성공 응답의 전체 User로 me 캐시를 갱신하며 이전 GET을 취소합니다. 프로필 수정이 인증 세션 발급/연장을 뜻하지 않습니다. 기존 쿠키/CSRF 초안과 Mock 메모리 인증을 유지합니다.
- 집계 0건은 완료 0편/중단 0편으로 표시합니다. 로딩·오류·재시도·미저장 이탈 안내는 최소 복구 UI이며 최종 디자인 승인을 뜻하지 않습니다.
- 16개 화면의 Mock 기반 기능 구현은 완료했으나 실제 서버 지속성·다중 탭·프로필 동시 수정과 실제 기기/WebKit은 P7/P8에 남아 있습니다. [구현 안내](13-profile.md)를 확인합니다.

## P7 E2E 결정 기록 (2026-11-21)
