# 마이·프로필 구현 안내

## 화면과 구성

P6의 `my`(773), `profile`(829), `profile-done`(849)을 구현했습니다. FigCraft MCP로 구조·문구·이동 대상과 렌더를 확인했습니다. 원본 `designs/`, `tools/`는 변경하지 않았습니다.

- `MyPage`: 현재 사용자 닉네임, 완료/중단 전체 건수, 이력·프로필·로그아웃 메뉴를 조합합니다. 집계 0건은 `완료 0편 · 중단 0편`으로 표시하며 조회 실패를 0건으로 위장하지 않습니다. 사용자 조회의 로딩·실패·401은 기존 AuthLayout, 집계 조회는 QueryFeedback으로 처리합니다.
- `ProfilePage` + `ProfileEditForm`: 닉네임만 수정합니다. 최초 서버 값을 폼 기본값으로 고정하여 백그라운드 조회로 입력을 덮지 않습니다. 가입과 동일한 Zod 닉네임 규칙을 재사용하며 trim 후 1~16자를 검사합니다. 미변경 값은 안내 후 요청하지 않습니다.
- `ProfileDonePage`: PATCH 성공 응답의 닉네임과 현재 사용자 ID를 담은 `{kind:'profile-updated',userId,summary:{nickname}}`를 검사합니다. 없거나 다른 사용자의 결과는 `/my`로 replace합니다. state는 인증 증명이 아니며 보호 라우트가 먼저 세션을 검사합니다.

기존 AppHeader, BottomAction, Button/ButtonLink, TextField, ResultView, QueryFeedback, LogoutButton, 하단 탭을 재사용합니다. 메뉴·프로필 요약은 작은 페이지 조합으로 유지합니다. 원본에 이메일 표시·편집, 탈퇴, 아바타, 추가 통계는 없으므로 추가하지 않았습니다. 기존 홈 헤더에는 사용자 이름이 없어 임의로 노출하지 않습니다.

## HTTP와 데이터 동기화

기존 GET `/me` (`getMe`), PATCH `/me` (`updateProfile`), GET `/records/summary` (`getRecordSummary`), POST `/auth/logout` (`logout`)을 사용합니다. 계약·생성 타입·MSW handler는 기존 구현으로 충족되어 변경하지 않았습니다. PATCH는 nickname만 보내고 MSW 사용자 Map을 수정하므로 후속 GET과 같은 세션 내 재로그인에도 변경값이 반환됩니다.

현재 사용자 캐시는 `['me']` 하나입니다. 인증 가드와 모든 사용자 표시가 `useSession`을 공유하고 별도 프로필 복사본이나 전역 store를 만들지 않습니다. PATCH의 전체 User 응답을 서버의 저장 결과로 사용하고, 진행 중인 `/me` GET을 취소한 후 캐시를 갱신해 이전 응답의 덮어쓰기를 막습니다. 요청한 사용자와 현재 캐시의 사용자 ID가 다르면 결과를 반영하지 않습니다. 성공 직후 불필요한 GET을 강제하지 않으며 다음 stale 조회에서는 동일한 API를 사용합니다. HTTP 테스트로 후속 GET의 저장값도 검증합니다.

프로필 변경은 세션 발급/연장이나 기록 집계 변경을 의미하지 않습니다. 집계는 `['record-summary', userId]`로 격리하며 기존 기록 CRUD가 무효화합니다. 로그인·가입·로그아웃은 기존 replaceSession으로 조회를 취소하고 다른 사용자 캐시 및 완료된 mutation을 제거합니다. 프로필 mutation의 보관 시간은 0입니다. 결과 history state의 사용자 ID 검사로 다른 계정의 이전 결과를 노출하지 않습니다.

401 저장 실패는 입력 이탈 차단을 해제하고 기존 세션 정리 후 로그인으로 복귀합니다. 403은 입력을 유지하고 권한/보안 정보 확인을 안내하며 세션을 임의 만료시키지 않습니다. 422 필드 오류는 닉네임에 연결하고 429는 Retry-After 동안 저장을 막습니다. 통신/5xx 오류는 입력을 유지하고 수동 재시도를 제공합니다. 자동 쓰기 재시도는 없습니다. pending 중 입력·중복 제출·내부 이탈을 막고, 미저장 상태에는 계속 작성/나가기와 탭 닫기 경고를 제공합니다.

## 디자인 비교와 검증 범위

375×812에서 FigCraft 세 화면과 Chromium 캡처를 직접 비교했습니다. 마이 인트로 24px 좌우/32px 상단, 메뉴 16px 외부/24px 내부 여백, 프로필 56px 앱바와 x=40px 입력, 결과 메시지 및 하단 56px CTA 구성을 대조했습니다. 메뉴 행 line-height와 프로필 label 색상을 보완했습니다. 글꼴 렌더링 차이를 허용하며 픽셀 동일성이나 최종 디자인 승인을 주장하지 않습니다.

- `e2e/profile.spec.ts`: 로그인부터 수정·완료·마이·재로그인, 미변경/공백/17자, 실패/중복/필드 오류/403/429/401, 이탈 취소, 집계 로딩/오류/재시도/0건, 백그라운드 입력 보존, 다른 사용자의 결과 접근을 검사합니다.
- `src/test/profile.test.ts`: 닉네임 경계·trim, 결과 소유자 검증, MSW PATCH→GET→재로그인, 사용자 캐시 격리, 늦은 GET 취소와 로그아웃 이후 결과 무시를 검사합니다.
- 320/375/430px·세 테마·모의 하단 safe area에서 가로 overflow 및 저장 버튼 접근을 확인합니다. 실제 기기 키보드/safe area, WebKit, 실제 서버는 미검증입니다.
- 테스트의 닉네임·이메일은 합성 데이터입니다. 캡처는 Git 제외 `test-results/`에만 생성하며 인증 폼/비밀번호/토큰 trace를 저장하지 않습니다.
