# 16개 화면 Visual QA (2026-11-21)

FigCraft 최종 원본과 React의 16개 화면을 375×812에서 대조했습니다. 주요 레이아웃과 이미지 비율은 유지되며, 선택창·보조 타이포그래피·safe area·가로 목록 키보드 접근성을 개선했습니다. 기본 모드에서 화면 접근을 막는 Critical 문제는 발견하지 않았습니다. 리디 대안 모드의 버튼 대비는 디자인 협의가 필요한 Major 잔여 항목입니다. P7 전체 완료나 출시 승인을 의미하지 않습니다.

## 기준과 재현 조건

- 기준 파일은 `designs/dokidoki.figcraft`입니다. FigCraft MCP로 파일을 열고 Screens의 16개 프레임, 내부 레이어·문구·컴포넌트·스타일을 조회한 후 모든 프레임을 1배율 PNG로 새로 내보냈습니다. 원본과 HANDOFF-QA는 수정하지 않았습니다.
- 디자인 출력은 `designs/visual-qa-2026-11-21/`입니다. 기본 팔레트, 375×812, Pretendard 기준입니다. `out/`의 과거 캡처나 HANDOFF-QA의 MAE를 React 합격 점수로 사용하지 않았습니다.
- 브라우저는 기존 Playwright Chromium, DPR 1, Vite 개발 서버, MSW `/api/v1`을 사용합니다. 기본 계정은 공개 Mock 도키, 완료 1편·중단 1편·추천 10편입니다. 실제 사용자 정보를 사용하지 않습니다.
- 가입·등록·수정·삭제·프로필 완료는 실제 폼과 Mock HTTP 성공 응답으로 진입합니다. 결과 state를 임의 생성하거나 인증을 localStorage로 대체하지 않습니다.
- 각 화면의 제목과 목록 수·필드 값 등 준비 조건, `document.fonts.ready`, 이미지 decode/정상 로딩을 확인하고 촬영합니다. 인증 입력 전과 성공 화면만 촬영하며 비밀번호 입력 화면은 저장하지 않습니다.
- 검색은 계약의 제목 정렬을 유지하므로 디자인 예시 순서와 다릅니다. 완료 화면은 원본과 같은 호리미야 5점, 청춘 돼지 수정 5점·삭제, 설렘수집가를 사용합니다. 강제 개행은 반응형 동적 데이터에 복사하지 않습니다.

```sh
npm run test:visual
```

`test-results/visual/`에 기본 16장, `responsive/`에 5개 너비별 80장, `compact/`에 375×500·모의 하단 inset 34px 16장, `states/`에 경계/복구 상태, `contrast.json`에 대비 측정값을 생성합니다. 테스트 실행 시 `test-results`는 재생성됩니다. 이번 검토의 원본·수정 전후 자료와 비교 갤러리는 로컬 `artifacts/visual-qa/2026-11-21/`에 보관합니다. 이미지와 로컬 갤러리는 Git에서 제외하며 테스트 코드와 보고서로 재현 방법을 관리합니다.

픽셀 기준 이미지는 승인하지 않았습니다. 자동 검증은 렌더링·이미지 로딩·가로 넘침·최대 폭·터치 영역·고정 영역·포커스·입력 경계 검증이며, PNG는 수동 비교 자료입니다. 폰트 래스터화, native UI와 원본의 강제 줄바꿈 차이를 픽셀 결함으로 일괄 판정하지 않습니다.

## 발견 사항과 수정 전후

|ID·심각도|수정 전 근거|처리 및 재검증|
|---|---|---|
|V01 · Major|홈 가로 목록에서 키보드로 다음 카드 이동 시 일부가 잘린 채 포커스를 받습니다. 외부 outline도 overflow 경계에서 잘립니다.|compact 카드의 키보드 focus에 nearest 스크롤을 적용하고 내부 outline을 사용합니다. 9개 카드 순차 Tab 이동에서 전체 가시성과 focus 표시를 검증합니다.|

|V03 · Minor|기록의 native select 화살표가 우측 끝에 붙어 원본 10×5px chevron과 다릅니다.|native select의 동작·label을 유지하면서 공통 장식 SVG와 우측 텍스트 여백을 적용했습니다. forced-colors에서는 native appearance로 복귀합니다.|

|V05 · Major · 미해결|리디 대안의 흰색 버튼 글자와 `#0F97FF` 배경 대비가 3.05:1입니다. 현재 16px 글자에 필요한 4.5:1에 미달합니다.|브랜드·전경 토큰 변경은 디자인 협의가 필요하므로 임의 변경하지 않았습니다. 리디 모드 제품 노출 전에 해소해야 합니다. 기본 밀리 버튼은 9.34:1입니다.|

## 반응형·접근성·상태 검증

- 전체 16개 화면에서 320/375/390/430px 및 1280px의 가로 넘침이 없고, 넓은 화면은 최대 480px 중앙 컨테이너를 유지하는지 자동 검사합니다. 입력 컨트롤은 44px 이상입니다.
- 375×500에서 하단 safe area 34px를 주입하고 dock과 spacer 높이 일치, 하단 고정 위치, 페이지 끝 콘텐츠 가림을 확인합니다. 실제 모바일 키보드가 열린 기기 검증과는 구분합니다.
- 기존 `styles.spec.ts`·`ui.spec.ts`로 비대칭 inset, 5개 폭, 긴 CTA와 콘텐츠, 폰트 실패, 세 팔레트 및 reduced motion을 검사합니다.
- 새 가로 카드 테스트는 실제 Tab 순회·포커스 표시·카드 가시성을 검사합니다. 320px·500px에서 매우 긴 작품 제목과 201자 중단 사유를 사용해 가로 넘침, 오류 연결과 첫 오류 focus를 검사합니다.
- 기존 테스트로 label/오류 연결, 접근 가능한 버튼 이름, 장식 이미지와 실패 대체, native select, 키보드 필터, 삭제 dialog의 취소/Escape/포커스 복원, skip link를 검증합니다.
- default/selected/success는 16개 화면과 기존 흐름으로, disabled/loading/error/empty는 인증·조회·mutation 테스트와 추가 상태 캡처로 확인합니다. 버튼 pressed는 기존 세 테마 테스트로 확인합니다. 별도 hover 디자인은 추가하지 않았으며 기존 마우스 동작을 유지합니다.
- 기본 밀리의 본문/배경 14.05:1, 보조 문구/표면 7.72:1, placeholder/표면 4.98:1, 버튼 9.34:1, 오류 문구/표면 5.12:1입니다. Threads의 검사 조합도 4.5:1 이상입니다. 이 측정은 명시한 토큰 쌍에 한정하며 전체 WCAG 적합성 인증은 아닙니다.
