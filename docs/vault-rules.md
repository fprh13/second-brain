# Vault 운영 규칙

## 1. 목적
이 Vault는 사용자가 본문에 원하는 내용을 먼저 작성하고, AI는 그 내용을 해치지 않는 범위에서 정리와 연결만 돕는 시스템이다.

핵심 목표:
- 사용자가 쓴 내용을 우선 보존
- 파일 위치 결정권을 사용자에게 유지
- 관련 노트가 잘 보이는 연결
- 최소 메타데이터와 읽기 쉬운 Markdown 유지
- Obsidian 그래프가 꼬이지 않는 구조 유지

## 2. 작성 원칙
- 사용자는 본문에 원하는 글을 먼저 작성한다.
- AI는 사용자 문장을 재작성하지 않는다.
- 치명적인 오타만 자동 수정할 수 있다.
- 가독성을 위한 Markdown 편집은 허용한다.
- 코드, 명령어, 설정, 로그는 반드시 fenced code block으로 작성한다.
- 한 `##` 섹션의 내용을 다른 `##` 섹션으로 옮기지 않는다.

## 3. 파일 위치 규칙
- 노트 파일 위치는 사용자가 결정한다.
- AI는 위치가 어색한 경우 더 적절한 위치를 추천할 수 있다.
- 노트 파일 이동은 사용자가 명시적으로 요청했을 때만 수행한다.
- 스크린샷, 첨부파일, 일반 파일은 `attachments/` 하위의 적절한 폴더로 이동시킬 수 있다.

```text
attachments
├─ diagrams
├─ screenshots
└─ files
```

## 4. 노드 연결 규칙
이 Vault는 노트 안에서 `관련 노트` 섹션을 중심으로 연결한다.

- 개념적 연관성이 분명한 경우에는 `관련 노트` 링크를 남긴다.
- 구조가 있더라도 템플릿에서는 링크 섹션을 `관련 노트` 하나로만 유지한다.
- 형식적인 링크를 억지로 채우지 않는다.
- 형제 노트끼리 무의미하게 전부 서로 연결하지 않는다.
- 기존 맥락을 무시한 교차 링크를 남발하지 않는다.
- 순환 구조, 중복 연결, 과도한 허브 연결은 피한다.
- `02 MOCs`의 노트는 필요 시 허브 노트로 사용할 수 있다.
- 적절한 연결 노트가 없으면 새 노드를 자동 생성하지 말고 공백만 보고한다.

## 5. 템플릿 및 메타데이터 원칙
`14 Templates`는 본문 작성 보조용이며 강제 폼이 아니다.

- 템플릿은 읽기 쉬운 기본 섹션만 제공한다.
- 템플릿에는 최소 필수 frontmatter만 둔다.
- 기본값으로 `created`와 노트 유형을 나타내는 최소 tag를 포함한다.
- `type`, 상태 추적용 키처럼 과한 frontmatter는 사용하지 않는다.
- 메타데이터는 꼭 필요한 경우에만 최소한으로 사용한다.
- 템플릿은 본문을 쓰기 쉽게 만드는 쪽으로 유지한다.

## 6. 점검 원칙
AI 또는 사람이 점검할 때는 아래 항목을 우선 확인한다.

- 중복되는 파일이나 중복 가능성이 높은 노트가 있는지
- 관련 노트 링크가 적절한지
- 그래프를 꼬이게 하는 링크가 있는지
- 파일 위치가 어색한 경우 더 적절한 위치를 추천할 수 있는지
- 첨부파일이 올바른 위치를 가리키는지

## 7. 운영 메모
- 파일 이동은 기본적으로 금지다.
- 첨부파일 정리는 예외적으로 허용된다.
- 템플릿은 현재 원칙에 맞지 않는 내용이 있으면 갱신하거나 제거한다.
- `11 Areas/취업/TIL`은 다른 사람이 작성한 학습용 참고 구역이다.
- 이 구역은 읽기 전용으로 취급하고, 수정, 구조 정리, 노드 연결, Git 추적 추가를 하지 않는다.
